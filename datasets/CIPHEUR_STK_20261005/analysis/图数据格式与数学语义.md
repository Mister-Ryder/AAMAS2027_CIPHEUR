# 新一轮 CIPHEUR 图数据

每个 `raw/CP-*-r*/contacts.csv` 是一个新 STK 机会库；`graphs/CP-*-r*/` 保存其所有约束配置。两个几何伙伴与多个 gap 是同一物理来源组的派生数据，不能算作独立 TRAIN/TEST 来源。原参数在 `source_plan/CIPHEUR_parameters.json`；图文件记录参数、程序、接触表、节点映射和权重的 SHA256。

建图程序为 `scripts/build_graphs.py`，版本 `cipheur-full-contact-capacity1-microtick-v1`。它不调用旧 V51 冲突分支、不求解优化问题、不调用 LLM，也不继承旧研究的证据标签。

## 冲突与收益

每个顶点是一段完整半开可见区间 `[s,e)`，权重恰为 `e-s`。单天线与单卫星容量均为 1。同资源按 `(start,contact_id)` 排序，较晚接触的起点严格小于较早接触的 `end+gap` 才连边；包含、同起点都冲突，恰好满足等号则兼容。卫星 gap 为 150 秒；P0 地面 gap 为 340、680、1200、1800 秒。

接触端点在 STK 导出阶段统一冻结为 6 位小数；17 位原始返回值、量化差值另存。建图阶段以 `Decimal` 读入并验证其精确微秒表示，拒绝非零的亚微秒尾数；不作进一步舍入。微秒 tick 是算法数值实例的序列化单位，不表示 STK 物理事件达到微秒精度。

## NPZ 文件

例如 `graphs/CP-AU-r000/g0340.npz` 可由 NumPy 直接打开，或调用 `build_graphs.load_graph(path)` 得到持久字典；不需要 pickle。

| 字段 | 类型 / 含义 |
|---|---|
| `contact_id`, `pass_id`, `satellite_id`, `site_id`, `antenna_id` | Unicode 数组，按 `contact_id` 排定共同节点顺序 |
| `start_ticks`, `end_ticks`, `weight_ticks` | int64 微秒 tick；权重为端点差 |
| `edge_u`, `edge_v` | uint32，唯一无向边，`u<v`，按字典序排序 |
| `edge_mask` | uint8 位掩码：1 地面、2 卫星、4 实际重叠、8 无重叠但间隔不足 |
| `indptr`, `indices` | int64 / uint32，对称 CSR 邻接；第 i 个节点邻接是 `indices[indptr[i]:indptr[i+1]]` |
| `base9_integer_coordinates` | int64，完整空边界下的数学 base9，语义详见下文 |
| `ground_gap_ticks`, `satellite_gap_ticks`, `ticks_per_second` | 标量；每秒 1,000,000 tick |
| `source_id`, `source_group`, `geometry_id`, `replicate_id`, `split`, `config_id`, `builder_version` | 标量元数据 |

同目录 `contacts_nodes.csv` 明确节点映射与资源，`g*.json` 记录边类型、分量、完整度分布、`2m/n`、哈希和边界敏感诊断。`summary.json` 只在该来源图构建完成后写出。

`edge_mask` 的资源位可同时存在；重叠 / 间隔不足表示该接触对的时间关系。图边不是一条物理卫星地面连线。

## 完整 base9 与证据界限

`exact_microtick_base9_v1` 的九坐标依次是：

1. weight；2. duration；3. active degree；4. active neighbor weight sum；5. active neighbor maximum weight；6. compatible active weight sum（去掉根及其邻居）；7. station gap；8. satellite gap；9. active count。

所有时间 / 权重坐标用 tick，计数坐标用整数。此文件中的向量仅对应所有保留接触均活动且 `F=X=∅` 的完整图。gap 是向量中显式坐标，因此不同 gap 的完整向量不会相等。

旧 `cipheur/graph_features.py` / `compiled.py` 对邻域和采用 `math.fsum` 的二进制浮点输出。新证据组的实际头若采用 Fraction 秒端点、Fraction weight / duration 和该 `fsum` 输出，须使用独立命名空间 `fraction_seconds_binary_fsum_base9_v1`。两个命名空间的 equality 不得混合。当前整数 census 是数学必要条件检查，不能替代实际头的完整 quotient。

收益 / 时长各不相同，可严格排除**不同接触**的完整 base9 精确碰撞，无论活动域或边界怎样变化，因为 weight 坐标始终保留。它不能排除**同一接触在不同状态**的向量相等，也不能证明跨状态 demanded quotient 无环。全图碰撞为 0 不能独立判断 G2 失败；完整严格要求、真实相等连接与 quotient 由证据阶段建立。碰撞存在、WL 可区分、配置反转也都不能单独证明表示不足。

## 阈值敏感记录

每图另统计同资源接触对的 `start_later-end_earlier-gap` 最小绝对值，以及绝对值不超过 0.002 秒的接触对数量，包含尚未连边的一侧。只将其作为数值阈值附近的诊断；Access Time Convergence 不当作严格物理误差界。如果这些接触参与关键证据，再对具体原 STK pair 收紧容差，无需全量重复仿真。

`analysis/graph_screen_summary.json` 和 `graph_screen.csv` 汇总已完成来源的图。跨库 duration census 不重复累计 gap 配置；统计单位仍为 `source_group`。

## P0 的实际数据与解释

已完成 4 个机会库、49,882 个完整接触和 16 张配置图，绑定 2 个来源组。每库 n 分别为 CP-AU-r000 的 12,467、CP-AP-r000 的 12,479、CP-AU-r001 的 12,471、CP-AP-r001 的 12,465。完整机会表的端点与资源保持原样；所有顶点权重严格等于冻结端点的 duration，同源四档的节点映射与权重哈希一致。所有配置图均为单一连通分量，因此不能仅凭初始图分量划分，把不同配置的全图条件值作未经声明的局部抵消。

对四个库，加严地面 gap 均满足 `E340⊆E680⊆E1200⊆E1800`。340→1200 分别新增 44,658、46,154、44,713、46,071 条边，相对原边数增长范围 53.0485%–57.4677%。程序还逐条确认新增边仅为地面间隔不足造成，既不是新实际重叠，也不是卫星约束变化。该事实说明本轮干预确实改变了冲突关系；它不推出动作偏好必然反转或任何算法收益。

完整图空边界的跨来源精确 census 共计 199,528 个动作发生项，得到 199,528 个不同完整 base9 向量，非平凡精确碰撞类为 0。该计算限定 `exact_microtick_base9_v1` 和 `F=X=∅`，详见 `fullgraph_cross_source_base9_census.json`。不同 gap 已由显式 station_gap 坐标区分；不同库的 n 坐标也不同。

完整窗口的 duration 没有被统一为人为时长，保留了大量端点差异；这些差异直接进入 weight 和 duration 两个坐标。在本批微秒冻结实例中，不重复累计 gap 时，只有 16 个 duration 重复类、32 个接触发生项，其余不同接触已被 weight 坐标区分。这是该批数据的实际等值连接库存，而非“结构不同必有严格标签”或“所有连续数据均无碰撞”的结论。对重复 duration 的接触，仍计算了其余全部 base9 坐标，完整图中没有获得相等向量。

这一筛选不能把全图 alias=0 扩大为 restricted-state quotient 无矛盾：同一接触在不同活动域可能再次得到同一完整向量，并通过不同边界的严格要求形成跨发生项连接或有向环。实际 G2 必须以云端证据组针对真实 patch、共同 `F/X`、实际头数值语义和全部已认证严格要求构建的完整 quotient 为准。当前输入 census 不代替该计算，也不决定进入 P1。

本批 16 图只有两个同资源接触对进入 ±0.002 秒阈值诊断范围。CP-AP-r000/g680 的兼容余量从 +0.001997 秒细化为 +0.001789571994 秒；CP-AP-r001/g1200 的冲突余量从 −0.000102 秒细化为 −0.00044295899 秒。独立的 15 秒步长、0.0001 秒收敛设置下两者符号均保持，原接触、原图和原 manifest 哈希未改。独立 receipt 在 `analysis/boundary_sensitivity`。该记录支持本次数值敏感性检查的稳定性，不能将收敛参数变成严格物理误差界。

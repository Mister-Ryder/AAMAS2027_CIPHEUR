# 输入复现与配置变化分析入口

固定输入的独立复现检查已完成一次。`input_reproduction_receipt.json` 保存完整记录：公开两个分卷按列明顺序重建为58,948,473字节，SHA256为 `d755572f53bc917d410e9fce9f67812ebe40c6344206eb545bc9406d52b1ac45`。归档包含128个图文件（16 TRAIN图和48新图各自的NPZ/JSON）及2个来源清单文件，合计130个成员。检查了分卷/成员hash、公开和本地输入一致、固定split、节点和精确权重不变、CSR/冲突边一致、实际每节点W/E间隔和资源边判据；没有求解器、模型、oracle或结果读取。

专家可将公开 `review_inputs` 两卷及manifest放在一个目录，把归档解压到工作目录，然后以解压出的 `heldout` 目录作为 `--perf-root`，运行实验 `scripts/reproduce_input_contract.py --review-root <分卷目录> --perf-root <解压heldout目录> --output <复现receipt.json>`。检查器再次从分卷在临时文件中重建并核hash，退出即关闭临时文件，不留下额外大归档。原有完整zip不是检查的必需输入。

首轮检查器曾因归档内额外的2个**来源清单**未列入外部manifest的图文件列表而停止；失败记录保留为 `input_reproduction_receipt.failed_inventory.json`。入口随后按真实合同分别验证来源清单与128图文件，并通过。该停止来自检查器的清单解释，不是输入文件变化。

配置变化分析的变化边在读取TEST结果前注册于 `configuration_response/configuration_response.registration.json`。固定13条有向变化：A→M/J/stress/W/E/MW/ME、W→J、E→J、W↔E、MW↔ME。

正式完成后先在云端对现有结果运行 `scripts/compact_selected_schedules.py --stage-root <正式TEST目录> --protocol <冻结protocol> --released-formal-results --output <selected投影.json>`。该入口仅复制保存的selected节点、身份和hash；不打开图、不重算结果、不修改主指标投影程序。所有选择均核原selected_set_sha256，原始resultSHA与失败job记录保留。

总任务释放正式投影后，再运行 `scripts/configuration_response.py --released-formal-results --selections <selected投影.json> --graph-root <perf_dataset_v1/graphs> --protocol <冻结protocol> --program-bank <冻结bank> --output <本目录/configuration_response>`。入口读取已有结果与固定图，只计算：图新增/删除边、旧选择在新图上的冲突边及涉冲突节点、新旧选择Jaccard、移除/加入节点收益、保存的最终质量差。它不会产生修复策略，不评分新程序，不改变冻结8程序、不调参、不择优。

涉冲突节点收益是所有unique涉冲突节点的收益总和；**不能等同于最小可行修复损失或必要损失下界**。跨配置最终质量差描述不同约束下的变化，不是同实例方法排名。所有方法和两批LLM都保留，统计单元仍为r008/r009，组内种子与AU/AP是重复测量。完整结果默认要求所有注册变化对齐，只有显式 `--allow-partial` 才生成清楚标为未完成的结果。

主完整性能比较仍由 `analyze_comparison.py` 处理，以上新增分析不替代主指标，也不改变程序选优规则。辅助机制scope若另行冻结，必须单独标注，不能混成主8程序的表示扩展效果。

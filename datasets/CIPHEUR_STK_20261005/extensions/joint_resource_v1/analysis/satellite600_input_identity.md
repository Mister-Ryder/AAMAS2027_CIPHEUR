# 卫星 600 秒轴的输入恒等结果

本单次开发扩展保留了 4 个机会库的 16 张图，原 STK 库和 P0 图文件不变。A=(ground340,satellite150)，G=(1200,150)，S=(340,600)，J=(1200,600)。600 秒是预先声明的开发压力值。

四个库都精确满足 `E_S=E_A`、`E_J=E_G`。不仅最终并集的新增卫星边为 0，卫星资源原始边数在 150/600 两档也完全相同；因此该结果并非卫星新边被地面边遮蔽。每节点 dS、同时两轴新增度为正的节点数、sum(dG*dS)、两轴新增边交集均为 0。新 satellite600 阈值附近 ±0.002 秒清单为空，没有启动额外 STK。

固定同一个机会/收益和声明状态 `(U,F,X)`，MWIS 可行集仅由边集确定，因此任一共同可用动作 a 都有 `Q_S(a)=Q_A(a)`、`Q_J(a)=Q_G(a)`。对共同竞争 a,b 的条件差值同样有 `ΔS=ΔA`、`ΔJ=ΔG`，所以四侧交互 `I=ΔJ−ΔG−ΔS+ΔA=0`。在该边界契约下 joint-only preference flip 不可能成立。这是图同一性的数学证明，不需要再次运行优化 oracle。

程序若因为显式参数坐标 150/600 改变而选择不同路径，并不能归因于 MWIS 可行集改变。负责人据此停止本扩展的批量四侧标签，不进一步抬高卫星 gap 来硬凑活性。该批产物保留为真实输入筛选记录，后续候选转向预声明的地面资源异质性。

详细输入与统计：`joint_graph_summary.json`、`joint_graph_screen.csv`、`new_satellite600_near_boundaries.json` 和各源的 `graphs/CP-*/summary.json`。后者还保留 per-node 新增度 CSV。

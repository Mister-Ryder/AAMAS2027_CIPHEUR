# 摘要与实现合同

## 研究目标与不降级原则

核心研究对象是**约束变化下的启发式程序合成**。LLM 生成完整解、标量分数迭代和一般反思演化都已有直接近邻。第二篇必须保留“同一对竞争决策、两侧均可行、完成偏好严格反转、可执行成对要求”这条核心链；不能退成普通 prompt 反馈优化。

DRAGON 细读见 `DRAGON_REVIEW.md`。DRAGON 的在线分解/重建、经验记忆、约束压缩与可行性检查已有实质设计。我们的创新假说是把受控约束干预转为**有正确性依据且可累积回放的程序行为规范**，研究证据如何改变程序。当前不能据此断言创新已超过 DRAGON，更不能声称性能优势。

## 条件完成空间

给定图 G、已提交集合 B、已排除集合 X、竞争动作 a,b：

`F(G,d;B,X) = {S: S 是 G 的独立集, B∪{d} ⊆ S, S∩X=∅}`。

目标 `V(G,d;B,X)=max_{S∈F} Σ w(v)`。对齐的 G/G' 保持节点 ID、节点收益、资源归属和时间窗相同，只改变一个合法约束参数。B 在两侧保持同样语义且均可行，X 相同；a,b 均属于两侧可行动作集合，在两侧均竞争。

每个下界附带满足全部图约束的完整可行选择集合，明确强制动作和边界承诺。偏好证书不能替代四个条件组合的可行性见证。

例如反转方向为左侧 a、右侧 b，只有满足以下条件才发证据：

`L(G,a) > U(G,b)+ε` 且 `L(G',b) > U(G',a)+ε`。

该证据证明此时的**条件完成偏好**，不证明生成程序全局最优，也不证明每次优先选它都能达到最优调度。

## 有限区域为何仍能给有效界

固定 B 和动作 d 后，先移除已阻塞节点。活动区域 R 内采用预算化分支定界；每个未展开搜索状态都保留有效上界，求解未完成时不会把 incumbent 当作最优。

- L：把区域内可行解扩展为满足全图冲突的区域外贪心完成，得到完整可行见证。
- U：区域内条件最优的有效上界，加上区域外所有可用节点的权重和。忽略跨区域冲突使可行空间扩大，因此 U 仍是全 residual 条件完成上界。
- 证据未成立：扩展两侧图的联合邻域，重新计算四界。预算或区域上限到达，记录无证据和已付成本。

因此本实现没有用孤立局部最优冒称全图条件值。外部权重和上界可能很松，也会因无关外部冲突拒绝潜在证据；大规模阶段需开发更紧的外部包络/分量界和有针对性的区域扩展。

证据算术使用 Fraction 表示已保存权重的精确二进制数值，运算过程中不舍入；导出浮点 L 朝下取整、U 朝上取整，严格不等式再按精确数值比较。日常调度报告收益采用稳定求和。`exact=true` 表示对应搜索空间的最优值已界定；非精确表示的浮点上下界仍可能相差一个刻度。

## 摘要承诺的代码映射

| 摘要机制 | 当前实现 | 当前限制 |
|---|---|---|
| Constraint-induced preference reversals | `aligned_intervention` + 四条件 `certify_pair` | 首版参数是单容量切换间隔；V51 使用旧规则 |
| Paired decision requirements | `requirement_report` 两侧严格评分排序 | 比较相同残余可用集上的优先级，不混用不同完成状态 |
| Context-dependent priority programs | 受限 AST 表达式，9 类残余结构/约束特征 | 种子只是运行夹具，表达能力和特征要正式消融 |
| Boundary-conditioned evidence | 固定 B、排除 X、全图见证和外部上界 | 当前界较保守，不能以大规模高效为已知结论 |
| Disagreement-directed acquisition | 在合法干预池中按未切换/冲突变化/低排序置信度排序 | 这是廉价代理，证书后再判断方向是否真的错误 |
| Joint assessment | 全部证据回放 + 完整训练/验证调度 | 本轮仅开发示例；不使用正式测试集选程序 |
| Fixed feasibility kernel, no online LLM | `schedule` 每次选择后删除冲突节点 | 只保证已建模图约束；容量>1一般约束不声称被普通MWIS表达 |
| Synthesis/optimization budgets | 轮数、calls、展开节点、时间、usage 和失败查询 | 还需正式统一模型/solver成本评估方案 |

## 让方法更有辨识度的实现方向

1. 将成对要求作为候选资格条件，所有新证据回放旧程序；LLM 不能只凭总分提升绕过已确认的行为要求。
2. 保存完整可行见证和外部上界，但向模型仅发送参数变化、两侧对齐特征、四个界与偏好，把证据正确性与提示长度分开。
3. 用当前程序选择查询，把错误方向与仅发生排序切换区分开；失败查询也纳入预算。
4. 程序修订失败时反馈具体错误和原候选，记录其来源，避免把后续手工修复算作模型成功。

这些是待验证贡献链的工程落实。后续新颖性判断应针对这条整体机制，与 HeurAgenix 操作反事实、EoH/其他程序合成、FunSearch 的外部评价等机制逐项比较，不能用“LLM + solver”作为创新描述。

# 后续推进路线

本轮范围：建立可运行底座，验证计算和接口正确性。用户明确允许暂不测试有效性，因此以下正式效果工作尚未开展。

## 阶段 A：让当前摘要具备真实自动合成能力

已具备 Responses/兼容接口、结构化候选、请求/响应冻结、拒绝反馈、程序归档和旧要求回放。下一步固定训练/验证实例，进行一次真实小预算合成，检查证据是否能被模型转为有效规则，之后再比较小模型与更强模型。调用成本、失败、令牌和人工干预分别记录。

当前助手种子允许底座先运行；正式 LLM 实验须使用真实调用记录，不能把回放次数或本轮手写程序算成合成效率结果。

## 阶段 B：把主动获取从给定池扩大为参数与残余状态搜索

从当前程序的调度轨迹提取 B/X 与候选对，在双方都合法的资源切换范围内搜索干预参数。先用廉价结构差异排队，证据求解再确认真实错误。无新增边、不可行边界、非竞争决策、界限不明分别统计，禁止只报告筛选成功的四次调用。

现有 V51 只读适配为下一步提供真实机会节点和精确旧约束。默认小前缀没有反转证据；应扩大到合理的时段/资源子集并核验合法参数范围，不能为了“出现反转”改权重或换节点。

## 阶段 C：加强证据提取辅助创新

研究联合邻域、边界阻塞签名、区域外分量上界、保守对偶界与渐进扩张。小图用精确穷举验证证书，大图用整数 CP-SAT/MIP 的有效界适配；新 solver 必须保留当前合同，不能把求解日志中的 incumbent 混称 upper bound。

目标是对相同查询成本取得更紧凑、更高比例的可靠反转要求。简化证据、删除外部影响或放弃两侧动作均可行都会降级核心机制，不能作为优化捷径。

## 阶段 D：正式对照与新颖性检验

冻结 split 和最终选择标准，测试集与未见约束组合只用于最终评价。准备以下对照，全部共用评分接口、kernel、程序长度约束和预算记录：

| 对照 | 要回答的问题 |
|---|---|
| paired vs scalar feedback | 成对行为规范是否比总分提示有效 |
| paired vs unpaired（相同上下文与数量） | 对齐及配对本身是否产生价值 |
| certified vs rollout preference | 有效条件界是否优于不可靠轨迹偏好 |
| active vs uniform acquisition | 当前程序驱动查询是否节省 solver 成本 |
| with/without boundary accounting | 外部机会成本是否必要，局部假证据如何影响程序 |
| LLM vs non-LLM expression search | LLM 是否带来超过同表达空间搜索的价值 |
| small vs strong model | 相同证据和合成预算下模型规模的作用 |
| conventional/exact solvers | 相同调度运行预算下质量与计算成本 |

代码中 `feedback=scalar/unpaired` 和 `strategy=uniform` 是可用的开发开关，但尚不构成公平正式消融：硬要求资格门槛如何保持/关闭、模型实际获取的信息、合成总成本需事先固定。不能只换开关就声称解决机制归因。

DRAGON 的在线 LLM 调用成本与我们的离线合成/多实例复用成本分开报告；如果跨问题比较，需适配其任务与实现而不是拿本文 MWIS 和其 TSP 分数直接比。

## 阶段 E：论文写作

以“受控约束变化如何产生可执行合成规范”为算法主线，星地链路调度负责展示实际资源耦合。理论至少覆盖条件完成界有效性、偏好证书可靠性和 kernel 可行性；不要把 kernel 可行性本身列成核心创新。没有证据的效率、泛化、性能提升不得写成已实现结果。

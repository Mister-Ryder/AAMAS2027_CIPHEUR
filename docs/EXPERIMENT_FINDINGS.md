# v0.2.0 初步实验：结果、边界与下一步

这轮实验把“条件完成值认证 → 表示矛盾诊断 → 类型化结构特征与规则联合评估 → 冻结部署”的基础链路落实到了可复核的项目中。它尚未证明 LLM 或定向表示细化的增量收益：定向联合、自由联合、无规范门控的质量—成本选择、非 LLM 枚举选中了完全相同的程序，而且该程序来自确定性枚举。在新的冻结程序复测中，联合程序的完整调度质量还低于若干强基线。当前应把论文结果定位为机制原型和初步实验，保留摘要的核心研究目标，并据此加强实验设计。

## 记录与核对范围

主实验记录为 `experiments/runs/pilot_v0.2.0`，审计后重跑为 `experiments/runs/pilot_v0.2.0_audited`；新实例复测为 `experiments/runs/followup_v0.2.0`。本分析读取各运行的 `summary.json`、逐实例 `test_metrics.json`、`test_reference_bounds.json`、规范与获取记录、冻结收据，以及主实验的候选、选择和数据协议。每种方法的逐实例目标值除以同一上下文的参照上界，再按实例族重算均值，与摘要记录一致。

审计重跑的 576 条记录与原主实验在目标值、质量比、选择集合、可行性和确定性特征工作量上逐条相同；严格规范结果也相同。冻结程序文件字节相同，SHA-256 为 `a6f194c48efd1e88e986769ddf2efeaf54ebf7c11283c7fe69a654c5ffc4746b`。复测直接复制该文件，未重新训练、生成候选或选择程序。审计重跑是实现核对，不是新的独立采样试验。

程序在线执行均无 LLM、条件值 oracle 或完整解参照求解调用。实验后的离线认证与参照求解用于测量，不能计入部署算法的在线能力。候选来源标记为当前编码助手辅助编写的原型候选库；自动化模型 API 调用数为 0，不能写成自动 LLM 进化实验。

## 数据范围与指标

主实验 train、validation、test 各含 36 个成对静态问题：12 个诊断探针、16 个随机时序问题、8 个 C3 来源子问题；每对有两个资源配置，共 72 个调度上下文。机会、时间、权重和标识在一对内部保持一致，资源约束配置改变。数据在取得 oracle 标签和程序质量之前生成，未按逆转发生、认证成功或质量筛选。

三个实例族应分别解释：

- 诊断探针刻意构造基本特征别名与局部结构差异，用于验证机制；它不是自然任务总体的抽样。
- 随机时序问题采用相互独立的训练、验证、测试种子与分离的目标约束配置，但仍来自同一个生成器。
- C3 使用 V51 原始冲突语义、按三天分别划分训练/验证/测试，再按时间窗及预声明资源分组取最多 28 个机会。主实验每个划分保留 224 个机会，全部划分共 672 个不同原始机会。源文件共有 69,923 个机会，本实验没有求解整个 C3 数据集。

主实验 72 个参照均求到精确值，8 种方法共 576 个调度均可行；其中 C3 的 128 个方法/上下文检查也通过原 V51 验证器。质量指标是完整可行调度目标值与相同固定/排除边界下最优值之比，包含边界已固定机会的收益。以下总体均值只是按本协议的上下文数量加权，不能替代自然分布性能结论。

训练获取 36 对中认证 34 对：8 对逆转、26 对保持，另 2 对因条件完成值相等无法得到严格偏好。随机时序与 C3 的训练标签全部是保持关系。主测试认证 34 对：12 对逆转、22 对保持，另 2 对条件值相等。每个已认证对产生两侧的严格排序要求，因此主测试有 68 条要求；未形成严格标签的问题仍保留在完整调度评估中。

## 候选选择解释

候选库共 48 个：34 个确定性枚举候选、14 个当前助手编写候选。18 个候选未增加特征，30 个增加一个特征。四种联合/枚举对照都选中枚举候选 `enum_discount_0.6_1.0`，其新增特征和规则为：

```text
neighbor_redundancy = sum_{(x,y) in E[N_active(v)]} min(weight(x), weight(y))
score(v) = weight - 0.6 * conflict_weight
           + neighbor_redundancy / max(1, degree)
```

该特征刻画候选冲突邻居之间的内部冲突，避免把所有冲突权重简单视为互相兼容的机会损失。它仅调用类型化图操作，不调用在线最优解或 LLM。

所选程序在训练上通过 60/68 条规范（88.2353%），验证完整质量比为 0.995141241067128。当前选择门槛为训练规范比例至少 0.75，随后按验证质量减去相对确定性特征工作量的成本惩罚选择，成本系数为 0.002。它不是“全部规范满足”的验证器，不能声称所有认证要求都被修复。

此候选库中，所有 30 个增加特征候选均消除了观测规范的精确别名矛盾，并通过 0.75 门槛；所有 18 个无新增特征候选均有矛盾且未通过门槛。因此，矛盾检查在现有规范门槛之外没有进一步改变候选集合。定向与自由联合共享同一个候选库、证据和评估预算，只能控制选择门控的作用，不能等同于两个独立的 LLM 生成流程。非 LLM 枚举仅评估其 34 个候选，也选中同一程序；此次没有显示助手候选的增量贡献。

`rule_only` 选择 `base_degree_0.6`，训练规范仅通过 42/68（61.7647%）；它是从基础表示候选中独立选择的对照程序，不能描述为通过门槛的规则修复。无新增特征候选中的最高训练规范通过率为 48/68（70.5882%），整个候选库最高为 66/68（97.0588%）。二者均不同于最后选择程序的 60/68。

## 主测试严格规范与完整质量的区别

| 方法 | 诊断要求 | 随机时序要求 | C3 要求 | 总体要求 |
|---|---:|---:|---:|---:|
| 四种相同联合/枚举程序 | 20/20 | 31/32 | 16/16 | 67/68 |
| 规则单独修复 | 0/20 | 30/32 | 15/16 | 45/68 |
| 权重 | 0/20 | 30/32 | 14/16 | 44/68 |
| 权重/度数 | 0/20 | 30/32 | 16/16 | 46/68 |
| 加权冲突 | 0/20 | 30/32 | 15/16 | 45/68 |

联合程序主测试通过率为 98.5294%，仍有一个严格失败：`random_temporal_test_0014` 的右侧逆转要求偏好 `n_339c5535`，但其得分为 −3.4375，竞争机会 `n_0144887a` 的得分为 −3.3999999999999995，实际排序相反。这不是接近相等得分的数值容差问题。高完整质量不能替代规范通过证明，也不能推出完整约束自适应保证。

诊断中的规则单独修复、权重/度数和加权冲突出现“20 条严格要求全部失败，但完整调度达到最优”的现象。两个指定根动作在原基本表示上具有相同特征，这些规则给出相同得分，无法满足认证的严格次序。精确别名商图中的自环/有向环由此证明：仅依赖当前精确特征向量的确定性逐动作标量评分不可能满足这些严格要求。

该证明的作用域是评分表达能力。它不证明任何使用这些特征的完整调度过程一定次优：内核可以先选外围机会，使根动作比较不成为实际决策，甚至绕开两个根动作。对 `diagnostic_test_0000` 的只读轨迹核查显示，左侧强基线先选择外围叶动作，最终两个指定根均未选中；右侧先选择外围动作，之后选入其中一个根。单位化左侧图中，选外围叶的完整值为 30，而强制指定根的条件最优值分别为 20 和 26，完整最优解可以绕开这组条件比较。固定 ID 的平局规则也可能恰好产生某侧可用选择，但不能把相同得分解释为同时满足两侧相反的严格排序。

因此，条件完成值认证回答“若在同一边界强制选择 a 或 b，哪种最优完成更好”；完整调度指标回答“整个内核最终选择的集合有多好”。下一轮必须同时记录规范动作是否进入真实竞争、到达状态下的条件遗憾及完整质量，避免用人工探针的评分差异直接宣称全局收益。

## 成本观察

确定性 `feature_work` 是图操作派发、成员/集合扫描、权重读取、聚合和算术等工作的显式代理，不是精确 CPU 指令数。主测试每上下文平均工作量：联合 12,235.4722，规则单独修复 11,139.4861，权重/度数 11,529.8611，加权冲突 11,842.3333。

在 C3，联合为 18,132.1875，加权冲突为 14,028.6875：质量几乎相同，联合代理工作量增加 29.2508%。这轮不能声称更好的质量—成本折中。成本惩罚与质量单独选择选到同一程序，也没有证明成本项的贡献。真实运行时间已记录，但同一个程序的四个标签也出现测量差异；单次、毫秒级计时不能用于宣称某标签更快。

## 新实例冻结复测

复测按照 `docs/FOLLOWUP_PROTOCOL.md` 扩大生成索引后，仅保留原测试范围之外的实例，并对原 train/validation/test 全部机会 ID、种子、实例/图指纹做交叉审计。实际得到 35 对新问题：12 个诊断、16 个随机时序、7 个 C3，共 70 个上下文。预声明的 16 窗口 C3 划分中测试窗口 14 没有符合资源条件的机会，按协议报告为空；没有按性能剔除问题。7 个新 C3 子问题包含 150 个未在原三划分出现的机会，节点数为 28、28、28、28、28、6、4。

复测使用原来已留出的测试约束配置，因此增加的是新实例，不是新约束分布。诊断拓扑仍来自同一探针构造；C3 时间窗由 10,800 秒改为 5,400 秒，不能把两轮 C3 差异全部解释为时间上的性能趋势。全部 70 个参照精确；8 种方法共 560 个完整调度可行，C3 原验证器 112/112 通过。

|---|---:|---:|---:|---:|

| 规则单独修复 | 100.0000 | 99.7317 | 99.3355 | 99.7445 |
| 权重 | 80.7249 | 97.0263 | 90.4200 | 90.1160 |

联合程序总体比规则单独修复低 0.0641 个百分点，C3 低 0.6541 个百分点，且 C3 工作量高 22.7655%；随机时序比规则单独修复高 0.1460 个百分点，却低于加权冲突 0.0699 个百分点。结果不支持一般质量优势。

复测认证 32 对（9 对逆转、23 对保持），形成 64 条要求；另外 3 对在两侧均为条件值精确相等，其中诊断 2 对、C3 1 对，记录为 `unknown/unresolved_bounds`，不能误写成 oracle 超时或错误标签。联合通过 61/64（95.3125%）：诊断 20/20，随机 29/32，C3 12/12。规则单独修复、权重/度数、加权冲突均为 41/64，权重为 38/64。联合的失败为 `random_temporal_test_0016` 右侧逆转，以及 `random_temporal_test_0027` 两侧保持，均是得分实际反序。保持关系失败说明仍需检验结构扩展带来的不必要偏好改变。

## 当前可支持的结论与限制

当前可以支持：原型可运行并保持可行性；全图条件完成值的上下界可给出逆转/保持证据；精确特征别名能证明特定评分接口的信息不足；类型化邻域结构特征能解决这些设计探针中的严格评分问题；冻结程序可在未用于选程的新实例上直接运行。

当前不能支持：LLM 优于非 LLM 枚举；定向证据生成优于独立自由生成；成本惩罚改善折中；保持规范具有独立因果贡献；无认证 rollout 标签一定更差；一般 C3 或大规模调度收益；对所有约束配置的排序或质量保证。先前及复测反例都应保留，不用测试反馈修改已冻结程序后仍称同一留出测试。下一轮按 [实验计划](EXPERIMENT_PLAN.md) 增加独立候选生成、结构族与规模，并报告配对不确定性。

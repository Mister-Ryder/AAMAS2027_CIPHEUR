## Root-approved execution amendment

For candidate positions, serialize Linux fitness in `(slot, run)` order, each with eight workers, never exceeding eight total fitness workers. Each run's next slot requires its previous feedback to be hash-verified and ingested. Complete/dispose the previous wave before starting the next. This pre-call amendment supersedes the old prototype document's serial run order and is frozen in the new transport binding and preparation registration.

The unchanged sequence is `i1,i1,e1,e2,m1,m2,m3,e2`, four runs, eight original slots per run. Work is reported and fed back but never breaks a quality tie. Failures remain original failed slots; there are no retries, replacements, extra calls or invented authored outputs.

Maximum assignments are four seed evaluations plus 32 candidate evaluations, each covering all 120 TRAIN states: 4,320 schedule assignments, with 2,160 summed nominal kernel-seconds.

# 面向最终摘要的分阶段实验计划

研究目标保持为：以经过认证的决策关系发现当前表示不能满足的排序要求，再引导 LLM 从类型化图操作库构造缺失的结构区分，并联合选择特征和规则，同时约束特征计算成本。诊断与联合生成是中心机制；逆转/保持认证和结构见证为它提供支持。初步结果不足时，应增强机制及对照证据，不能把论文降级成只有规则改写或简单反例修复。

## 已完成的基础阶段

v0.2.0 已完成数据划分、固定可行性内核、完整条件值认证、精确别名商图诊断、类型化特征、安全评分表达式、联合选择、冻结收据及运行追溯。主实验与审计重跑的冻结程序和非计时结果一致。冻结新实例复测也已完成，未重新选择程序。详见 [实验分析](EXPERIMENT_FINDINGS.md)、[原始数据协议](DATA_PROTOCOL.md) 和 [冻结复测协议](FOLLOWUP_PROTOCOL.md)。

现有结果是原型证据：四种联合/枚举标签选中同一枚举程序；主测试规范 67/68，新实例规范 61/64；强基线整体质量已很高，复测联合程序在 C3 反而低于基线。自动 LLM API 调用为 0。目前不能把同一候选库的重复选择当成 LLM 独立试验或定向生成收益。

## 研究问题与预声明指标

| 研究问题 | 主要比较 | 主要测量 |
|---|---|---|
| RQ1：表示矛盾诊断是否能指向规则修复无法解决的信息缺失？ | 定向联合、固定表示规则修复、预声明结构枚举 | 精确别名自环/环、可满足比例、严格规范、到达状态条件遗憾 |
| RQ2：证据指导的 LLM 生成是否优于同预算自由联合生成？ | 独立定向 LLM 与自由 LLM 生成流程 | 每预算产生的有效候选、规范/质量/成本、不同试验的稳定性 |
| RQ3：严格认证与保持关系是否改善可靠性？ | 完整证据、去保持证据、rollout 偏好替代 | 错误标签、未决比例、保持破坏、完整质量与失败轨迹 |
| RQ4：成本约束是否改善表示扩展的实用折中？ | 联合成本选择、去成本项、惩罚系数扫描 | 工作量、真实特征耗时、评分耗时、质量—成本曲线 |
| RQ5：冻结程序能否跨实例/配置及规模泛化？ | 同实例族留出、结构族留出、配置留出、较大 C3 窗口 | 完整可行质量界、规范、节点/边数、耗时与内存 |

完整调度质量和严格关系一致性应作为不同维度并列报告，不能相互替代。把成本与质量一起列为主要结果，提前固定预算和选择规则。所有数据族分别报告，再给声明权重的汇总；保留没有形成严格标签的问题，并报告认证覆盖率。非精确参照场景报告目标值/上界、下界/上界和参照求解预算，不把上界当最优值。

## 阶段一：增强证据与结构覆盖

1. 增加不同结构见证来源：邻居内部冲突、多个资源关联的二跳结构、加权兼容集合、边界已固定/排除动作下的依赖。训练、验证、测试的结构族预先划分，减少单一探针模板重复。保持原始基本表示，新增区分由证据指导，避免把所有高级特征预置后只调系数。
2. 自然随机/C3 训练中补充更多预声明候选对与边界状态。目前它们训练没有已认证逆转，不能充分训练自适应要求。获取流程按固定规则或预算选查询，不查看留出集质量后挑选“有利”对。
3. 记录认证动作对是否进入真实内核的可选集、是否为该步的有效竞争、何时被删除。对实际到达状态独立计算条件值界与条件遗憾，并保留完整调度结果；设计探针继续用于验证表示不可满足命题，但不把它的评分改善直接折算成全局收益。
4. 在训练内划分发现/评估子集或采用预声明轮次。因失败轨迹新增训练证据时，新版本须重新冻结，并使用新的留出实例/结构/配置；原主测试与新实例复测永久保留为 v0.2.0 记录。

精确数值别名才用于“不可能满足”的证明，近似别名只能作为查询和结构提示。商图无环只说明有限观测要求不存在这种顺序矛盾，不证明某个受限 DSL 可以表达满足它们的规则。认证必须针对同一明确边界和全问题有效条件完成值，不用局部无边界 rollout 代替认证。

## 阶段二：真正独立且预算匹配的生成对照

在可用模型调用环境建立后，运行至少三个独立生成流程：定向联合、自由联合、固定表示规则生成。前两者具有相同类型化图操作库、规则语言、可行性内核、数据、候选评估器和可用预算；定向流程获得矛盾与结构见证提示，自由流程可以使用相同训练关系和质量反馈，但不接收表示矛盾定向指令。固定表示流程禁止增加特征。另保留预声明系数网格/结构组合的非 LLM 枚举对照。

候选预算、token/模型预算、oracle 调用与搜索节点、完整验证调度评估次数、总耗时均须记录；无效输出和重试计入调用预算。不同 LLM 流程的候选库独立生成，不能用共享银行替代这一比较。为了单独识别诊断门控作用，现有共享候选银行实验仍可保留为补充控制。

每个流程预声明多次独立采样重复，保存完整输入证据、提示版本、模型标识、采样配置、原始响应、解析与拒绝原因、候选 AST、评估日志和最终冻结哈希。相同程序在不同标签中出现时明确标记，不把它当成不同发现。编码助手人工参与、自动化模型调用、确定性枚举的来源逐候选区分。

当前缺少真实自动化模型调用，因此这阶段尚未执行；不能填入假调用记录或声称通过当前助手完成了独立 LLM 多次试验。已有 provider 接口可支持后续接入，当前助手可以继续形成可审查原型候选，但它们仍归入助手辅助来源。

## 阶段三：支持机制与成本消融

- **保持规范消融：** 保持总训练查询/评估预算相同，比较完整逆转+保持证据与仅逆转证据；不得简单删除标签后享有更少约束且称同预算。测量新配置中正确保持的比例、错误改变，以及完整质量。复测的两侧保持失败是需要解释的具体反例。
- **认证消融：** 在相同成对问题、边界、候选动作和声明计算预算下，用有限 rollout 偏好替换 sound bounds，比较可认证覆盖、标签错误与最终程序。严格认证可能保留未决，须报告其成本和覆盖优势/损失；不得把未决算成错误。
- **矛盾/见证消融：** 分别去掉矛盾触发或结构见证内容，并保持模型/候选评估预算匹配，区分诊断、提示信息与候选选择各自作用。
- **成本消融：** 固定候选库验证选择项，再以独立生成流程验证成本反馈的影响；比较去成本项与预声明多个惩罚系数。报告完整选择曲线和失败规范，避免只展示某个有利系数。成本代理与实测时间分别报告，增加重复计时、预热与一致硬件/进程条件。

当前主实验的成本项与质量单独选择选出同一程序，不能视为成本贡献证据；C3 高工作量、几乎相同或更低质量的结果要作为待修复问题保留。

## 阶段四：更大规模与真实 C3 验证

逐级扩大预声明的 C3 时间窗、资源组和机会数量，最终测量不受 28 节点上限限制的实例。继续沿用原数据/冲突语义，并在原 V51 验证器中核查输出。时间切分、机会去重、资源配置和空窗处理必须写入协议；原始 ID 用于跨划分审计。

小图可使用精确参照；较大图在固定预算下使用 sound lower/upper bounds，并报告参照缺口和节点开销。认证查询也可未决，不能为了增加标签而改用未声明的近似 oracle。绘制节点数、边数/密度、特征工作量、特征耗时、评分耗时、总耗时及质量界随规模变化。可缓存的共享子表达式应使用统一实现，不能只给目标方法缓存。

当前 C3 源于单一数据集的三天、受限资源分组与小窗口，泛化范围有限。若取得更多实际任务/日期，应做独立日期或任务留出；没有新增来源时，论文只写资源与时间窗子问题结果，不声称真实全量调度优势。

## 阶段五：配对统计与论文证据

逐方法采用相同上下文的差值，再按成对静态问题聚类进行 bootstrap 或其他预声明配对统计。两侧配置来自同一对问题，不按两个独立样本计数。按实例族分别给区间和失败比例；C3 窗口共享少数日期，区间也不能解释为任意任务总体置信度。模型多次生成的随机性与实例采样不确定性分开呈现。

配置中的 `bootstrap_replicates=2000` 只是计划参数；在统计产物产生并核对前，不写任何数值置信区间或显著性。审计重跑和同一冻结程序的不同标签不增加独立试验数。复测可单独报告，也可按事先声明权重补充汇总；不得在观察结果后改权重以改善总体指标。

论文基础版本先给出已实现方法、不可满足命题及作用域、明确协议、两轮原型结果、完整反例和限制。要支撑最终标题中 LLM 指导的实证贡献，还需真实可追溯的独立 LLM 试验、预算匹配生成对照、结构/配置留出和规模证据。若对照仍没有收益，应保留结果，改进证据获取或表示合成机制后重新冻结测试；不通过删强基线、隐藏反例或改变术语宣称创新已获证明。

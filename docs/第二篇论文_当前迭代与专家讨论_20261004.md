## 2. 算法上：当前方法与正在修正的环节

### 2.1 求解问题和“适应”的具体含义

主模型把卫星—地面通信接触选择写成加权冲突图上的最大权独立集（MWIS）。每颗卫星、每个地面站容量为一；切换间隙等约束参数改变冲突边。固定边界 `B=(F,X)` 分别表示永久承诺和永久排除。

适应能力指：在两份分别静态求解、动作及边界保持对齐的约束配置中，同一对竞争动作的合理排序可能翻转或保持，冻结规则能否响应这种变化。当前方法及实验没有建立运行过程中在线更改约束的动态调度能力。

### 2.2 当前算法链条

1. **认证决策需求。** 比较在同一图、同一边界下承诺动作 `a` 或 `b` 后的全残余条件完成值。对完整且完全相同的残余连通分量作相消，用可行独立集下界、团覆盖上界和有界精确搜索给出差值区间。区间能确定严格符号时保留偏好；平局和无法确定的情况分别保留。
2. **检查现有输入是否足够。** 将具有完全相同实际特征向量的观测合并成商图顶点，把认证严格偏好写成有向弧。自环或有向环说明：仅依赖该输入向量的确定性标量规则无法满足全部保留需求。
3. **给 LLM 可操作的修复见证。** 见证包含具体偏好弧，以及使矛盾成立的特征相等连接（equality joins）。离线 LLM 在类型化图操作库中联合构造新增特征与评分规则。
4. **完整复检。** 每次候选修复后重建所有保留严格需求的完整商图。消除一个局部见证可能暴露另一个环，必须继续检查。信息门只计规则实际引用的新增特征；声明了却没有使用的特征不能冒充输入修复。
5. **联合评估和冻结。** 候选先通过语法／有限数值、需求商图无环和 TRAIN 可行执行门槛；再依次优先选择严格排序拟合 `m`、完整调度质量 `q`、较低计算工作量 `c`，最终按原始位置破平局。质量对照使用另一套预先固定的质量选择器。
6. **共同内核执行。** 冻结规则控制局部 greedy additions 和 pivots；初始化、patch 构造、搜索边界、可行性检查和正增益提交保持共同。在线部署不调用 LLM，也不调用全残余认证 oracle。

### 2.3 成熟算法组件如何进入框架

性能批次有两个执行分支：cold 使用 Degree 初始化；warm 使用原生 CHILS 的半目标预算初始化，再用相同的半目标预算局部 repair。共同内核采用可行 incumbent、团界、有界加权 branch-and-bound 和正增益替换等成熟原语。

每个 warm 策略按单独部署计算时，承担完整初始化准备、调用、检查、子进程 CPU 和自身 repair 成本。批次共享一次初始化的工程安排，不会从单独部署成本中删掉这项开销。

CHILS 是实际使用的共同优化组件。M²WIS、Struction、WeightedBR 按当前稿引用的已发表算法作为独立原生对照。**应把共同求解底座的性能与合成表示／规则带来的增量分别报告。**

### 2.4 正在补的关键算法验证：全残余标签 → 局部部署排序

认证标签比较的是固定边界下的全残余完成值，实际 repair 却在临时保留外部 incumbent 的局部 patch 内执行。因此，全残余标签拟合好，并不直接证明局部排序或 pivot 更有效。

已经冻结并排队的 **TRAIN restricted-patch bridge** 用于检验这个接口：分别报告实际局部子问题和完整残余范围的排序证据，以及 core／full-strict 配对层的结果。即使局部 inclusion preference 拟合改善，也不能自动称为 pivot 效率认证。

## 3. 思想上：目前的论文主线

主线是：**先诊断当前输入能否表达正确决策，再联合修复输入和规则，最后检验真实求解后果。** 这个方向在 V05 已存在，V06 正在把它落实为可区分、可验证的三层问题：

| 层次 | 要回答的问题 | 当前修正的关键点 |
|---|---|---|
| 信息层 | 当前特征能否区分认证需求？ | 精确商图、自环／有向环、规则实际使用的特征 |
| 规则层 | 有限语法下生成的标量规则是否真的排对？ | 严格拟合及 margin 单独测量，翻转／保持要求两侧共同正确 |
| 求解层 | 排序改变能否改善完整可行解，成本是否值得？ | 相同内核、相同初始化条件、实际质量／时间／工作量／覆盖率 |

三层不能互相替代。商图无环，只能说明有限观测点上存在某个不受语法限制的标量函数；它不保证当前 LLM 规则学得出来，不保证留出正确，也不保证高调度收益。

最新会话接受的方向是把成熟优化算法作为共同底座，把框架贡献集中在**认证冲突如何指导缺失信息的补充、规则如何适应约束变化，以及这种补充的成本**。论文主表准备先展示实际性能与适用范围，再用机制结果解释贡献。

## 4. 创新角度上：能主张什么，边界在哪里

### 4.1 当前最有希望成立的贡献组合

**认证偏好 → 输入商图冲突 → 具体相等连接见证 → 有类型、有成本的特征—规则修复 → 完整商图复检 → 冻结部署验证。**

关键在于把“表示无法表达”和“规则拟合不好”分开，并给出可操作的修复依据。当前论文已承认 EoH、ReEvo、FunSearch 等程序生成方法能够构造结构表达式；“LLM 能发明结构特征”本身不宜承担主要创新主张。

| 贡献候选 | 现有支持 | 必须限定的范围 |
|---|---|---|
| 认证决策证据 | 完整条件完成值差的有界认证，保留平局／弃权 | 指定图、边界和动作的条件值；不能直接认证部署 pivot |
| 精确输入矛盾诊断 | 商图无环与有限点上标量可表达性的对应关系，具体环见证 | 不保证有限规则语法可表达、学习成功或泛化 |
| 成本敏感的表示修复 | 有限目录精确 cut loop，并有已完成的最小成本实例 | 固定证据、固定目录、独立正加性成本；不等于共享计算后的实际运行时最优 |
| 约束适应型合成框架 | R2 中 witness 条件的较高信息门通过率 | 当前是共同 warm seed 下的条件性 TRAIN 结果；留出和完整质量收益待验证 |

实际 LLM 候选库使用商图门槛和联合选择，**没有自动继承有限目录精确 master 的最优性保证**。

### 4.2 本简报的研判：最需要专家判断的创新风险

“有限观测商图无环即可赋予标量排序”这个命题本身较基础。论文价值更可能来自认证需求、可操作见证、成本修复和真实部署验证的闭环。专家应重点判断这个组合相较已有程序合成／反例引导方法的增量是否充分，以及哪些实验能证明见证真正发挥作用。

另一风险是单一高收益叙事过强：当前 W 的信息门通过率更高，但 R 的平均实际拟合和选中工作量更好。若把“信息修复”直接写成“综合性能提升”，会与已得到的证据冲突。

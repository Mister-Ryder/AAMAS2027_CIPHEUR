# V07 public satellite/ground-contact scene sources

Source research date: 2026-10-04. Only primary project/author, official proceedings and space-agency pages were used. No arXiv source is cited. No large dataset, binary ephemeris or raw radio artifact was downloaded; no propagation, label acquisition, optimizer or benchmark was run. This note complements the local C3 data and the draft scene contract; it does not introduce a user-approval requirement or start an experiment.

**Recommendation:** use CelesTrak orbital elements plus a frozen real station registry for a scalable, physically derived visibility scene, and use SatNOGS historical metadata to calibrate/check the scene. Label this **derived simulation**, not a real complete contact-request benchmark. Investigate SatNet as the stronger real-request scheduling source if its license and richer problem contract can be resolved. EarthSight supplies a formally published, openly licensed simulation artifact that can reduce geometry-engineering effort, but is a secondary route rather than a replacement for the existing scheduler.

## 1. CelesTrak + SatNOGS: recommended scalable physical geometry

### Verified official inputs

CelesTrak publishes GP orbital elements through OMM-compatible CSV/JSON/XML/KVN queries, including selection by catalog number or satellite group. These provide satellite identity, element epoch and orbital mean elements suitable for the documented SGP4 model. Prefer OMM-compatible CSV/JSON rather than a legacy fixed-width TLE-only parser, so larger catalog IDs are supported. [Official GP formats and queries](https://celestrak.org/NORAD/documentation/gp-data-formats.php).

The official access policy permits free retrieval while limiting repeated requests: cache required snapshots, fetch only needed data and at most once per update, and stop machine queries on non-200 responses. This research did not establish an explicit unrestricted redistribution license; public accessibility must not be relabeled CC0/public domain. Publish a source/epoch/query/hash manifest and regeneration recipe while separately establishing raw-data redistribution terms. [CelesTrak usage policy](https://celestrak.org/usage-policy.php).

SatNOGS explicitly states that its API is publicly accessible and API data are CC BY-SA; its license link resolves to version 4.0. Its API root exposes station and observation resources. These provide real network provenance and geography rather than randomly invented station positions. [Official API documentation](https://docs.satnogs.org/projects/satnogs-network/en/latest/api.html), [API root](https://network.satnogs.org/api/), [license](https://creativecommons.org/licenses/by-sa/4.0/).

The official client documents job fields `id`, UTC `start/end`, `ground_station`, `tle0/1/2`, `norad_cat_id`, `frequency`, `mode`, `transmitter`, `baud` and `max_altitude`. Its client location contract uses longitude, latitude and elevation; station installation also records minimum horizon and receiver/antenna frequency range. These are meaningful checks for visibility/radio eligibility and duration. They are not mission-priority weights. [Client field example](https://docs.satnogs.org/projects/satnogs-client/en/stable/modules.html), [official location/station configuration](https://gitlab.com/librespacefoundation/satnogs-kit/blob/master/instructions.rst).

### Derivation and scale — proposed, not executed

Freeze a non-outcome-selected satellite set, actual station coordinates/elevation/horizon and an orbital snapshot available at the specified prediction time. Propagate once using a pinned implementation and frame/time/Earth-orientation contract. Find all visible intervals above the frozen elevation horizon, respecting the explicitly modeled receiver bands. Store satellite, station, UTC acquisition/loss of signal, duration in seconds, orbital epoch, geometry assumptions and input hashes. Repeated orbital passes over the same geography produce recurrent resource structure without copying a favorable toy.

For a fixed set of candidate contacts, only change the operational transition/switching gap when rebuilding constraint graphs. Do not regenerate times, weights or station locations per gap. A sufficiently large satellite/station/horizon selection can yield hundreds or thousands of windows, but the exact node count/density is unmeasured here. Freeze a calendar/horizon rule and retain all opportunities; do not keep extending time until a favorable alias or algorithm advantage appears.

TRAIN can use earlier time blocks and TEST later blocks from the same selected constellation/station grammar. This is chronological transfer, not independent random-seed replication. Shared spacecraft/orbits and neighboring days remain statistically dependent. Forecasts far from an element epoch are uncertain; retain epoch-age diagnostics and clearly separate a fixed-snapshot forecast experiment from later observed windows or refreshed-ephemeris replay. Do not expose future TEST windows or their certificate labels to authors merely because their geometry can be generated in advance.

### Essential scene-fit limits

- SatNOGS observations are already selected/scheduled jobs and receiver outcomes, not a census of every feasible competing opportunity. Using only them can remove contention. Generate all declared eligible visibility opportunities for scheduling, with metadata used as calibration/provenance, not as optimal-selection labels.
- SatNOGS is a receive/observation network. A broadcast satellite can be observed by multiple sites; **single-capacity satellite service is not automatically a real SatNOGS constraint**. A dedicated point-to-point downlink experiment must state that additional operational contract. Station antenna/receiver concurrency must also be declared, rather than treating a site ID as a universal single antenna.
- Orbit/geography supplies window structure, not mission demand, priority, RF performance or actual slewing/retuning gaps. Duration-as-reward in seconds can match the existing objective only under an explicit fixed-track/service contract. Do not draw unsupported quarter-valued reward classes or quantize durations merely to force exact feature aliases.
- Exact full-base-nine aliases and preference reversals must be measured after the scene is frozen. Recurrent passes or graph isomorphism do not establish a change of preference under a configuration intervention.

## 2. SatNet: strongest public real-request scheduling candidate

The author repository identifies itself as the SatNet dataset/environment and links its formal IEEE Aerospace Conference paper (document 9438519) and AAAI ML4OR Workshop paper. The latter describes five oversubscribed 2018 weeks, with 12 antennas and 257/294/293/333/275 requests in weeks 10/20/30/40/50. The data include mission requests and valid view periods, requested/minimum duration, setup/teardown and antenna availability; antenna maintenance is supplied separately. This is operational-request evidence, not independent-uniform synthetic contacts. [Author repository](https://github.com/edwinytgoh/satnet), [formal IEEE publication](https://ieeexplore.ieee.org/abstract/document/9438519/), [AAAI ML4OR workshop primary paper](https://openreview.net/pdf?id=buIUxK7F-Bx).

**Feasibility:** earlier weeks can form TRAIN and later weeks held-out TEST while retaining the recurring DSN mission/antenna structure. The five-week collection is finite; it cannot by itself support arbitrarily many independent periods. Candidate track alternatives could produce a large conflict graph, but their expansion must be deterministic and budget-independent. No instance/file payload was inspected or downloaded in this search, so exact contact-node counts are not asserted.

**Mapping:** this is not immediately the current fixed-contact MWIS problem. Native SatNet includes choosing/clipping/splitting tracks within view periods, meeting request-duration conditions, antenna combinations and maintenance. A derived fixed-track problem can freeze candidate start/end alternatives and encode competing resources, but must preserve or explicitly restrict request-level constraints. Pairwise conflict edges alone cannot silently stand in for all original split/total-duration requirements. Keep setup/teardown in their documented units and intervention semantics. Results on such a restriction would be a **SatNet-derived fixed-track study**, not a solution/reproduction of the unrestricted DSN benchmark.

**License/access:** the inspected author repo root and README expose no explicit license; do not claim permissive redistribution. The GitHub metadata API returned a rate-limit error, and the live IEEE/OpenReview fetches were partly blocked; paper details above were available in the official indexed primary workshop text. Licensing remains unestablished. This does not imply a need to ask the user again for routine work; it limits what can be asserted or redistributed. NASA/JPL's current operational scheduling portal is not a substitute: its scheduling links explicitly require JPL LDAP/VPN. [Official JPL access scope](https://rapweb.jpl.nasa.gov/).

## 3. EarthSight: formal published simulation artifact

EarthSight is published in the official MLSys 2026 proceedings and has an author-maintained MIT-licensed artifact. Its reference-data layout lists Planet satellite TLEs, ground-station locations, JPL ephemeris and scenario definitions; source modules cover orbit mechanics, satellite-ground visibility, routing/downlink and ground scheduling. It is a simulator-based imagery/runtime study, not a released historical contact-request benchmark. [Official proceedings](https://proceedings.mlsys.org/paper_files/paper/2026/hash/26289c647c6828e862e271ca3c490486-Abstract-Conference.html), [author artifact](https://github.com/scai-tech/EarthSight), [MIT license](https://github.com/scai-tech/EarthSight/blob/main/LICENSE).

**Potential use:** inspect/reuse the small geometry/scenario components and explicit real station/TLE inputs to derive contact windows using one pinned scene model. Extend a fixed calendar into later TRAIN/TEST periods, preserving spacecraft/station structure while withholding new opportunities. This is an adaptation and derived simulation; its original compute/image-query priorities are not automatically contact weights or mission service requirements. Freeze visibility thresholds and transition-gap semantics independently of scheduler results. Code MIT licensing does not by itself establish the original rights/provenance of each bundled third-party reference file.

**Scale/cost:** the author README states full simulation jobs require 256 GB RAM and roughly 12 hours for 48 simulated hours, and distinguishes available/functional artifacts from some unreproduced results. Do not run or import the full imagery workload simply to obtain geometric opportunities. Actual extracted window count and the suitability of its station/constellation set are still unmeasured. This route is secondary to direct CelesTrak/SatNOGS geometry and local C3. [Artifact requirements and structure](https://github.com/scai-tech/EarthSight).

## Sources not promoted to primary benchmark

NASA SOHO provides a documented DSN schedule format with begin/end UTC, duration and antenna ID, originating from JPL scheduling products. It is useful for seconds-based track/switching context and archival format checks, but a one-mission **selected schedule** is not the complete multi-mission competing-window/request population required here. It should not be inflated into a large conflict benchmark by duplicating tracks. [Official SOHO DSN schedule documentation](https://soho.nascom.nasa.gov/soc/soc/info_files/dsn_schedules_info.html).

The JPL Service Scheduling Software page confirms real request-driven DSN scheduling, but does not establish a new openly downloadable full request corpus. It supports domain interpretation rather than the claim that operational DSN production data are unrestricted. [Official JPL SSS project](https://ai.jpl.nasa.gov/public/projects/sss/).

# Execution-budget amendment

Programs, candidate banks, training evidence, validation selection and test contact allocation remain unchanged. No test quality outcomes were read or used to tune candidates. During the initially unbounded evaluation, the no-cost selection control g18 repeatedly recomputed residual cover/greedy completion statistics; eight workers had consumed fourteen minutes while 160/840 contexts had completed. This revealed an execution-harness omission: per-program inference had no declared limit.

A separate bounded evaluation uses five process-CPU seconds per frozen constructive program, retaining timeout rows with no returned schedule. No automatic repair/fallback program is substituted. Completed-schedule quality, timeout/completion rate, and CPU/wall costs must be reported together. Timeout cannot be removed silently or assigned the quality of a partial/fallback schedule. HiGHS remains the independent ten-second reference and local search its own two-second comparator; these are not claimed to be matched inference budgets.

Original unbounded records are preserved separately. The change concerns evaluation limits, not synthesis or test-driven selection. Main primary inference comparisons use the bounded run; the unbounded pilot is an execution-cost diagnostic. Offline held-out evidence audits concern primary generated arms and fixed baselines, rather than re-running the entire expensive no-cost control during every relevance calculation. No deployment call receives evidence or oracle results.

The bounded002 primary harness failed after 207/840 saved context rows (its last ten-row progress checkpoint reports 200): local-search initialization called `max` on classical baseline rows containing both floating rewards and `None` timeout values, raising a `TypeError`. An earlier signal-stall interpretation was unproven and is superseded by this recovered traceback. The immutable saved bounded002 amendment retains that older explanation; this document records the correction. Transfer bounded002 completed all 216 contexts. The final preserved unbounded001 archive contains 182/840 rows (last progress checkpoint 180); the earlier 160 count describes the fourteen-minute progress snapshot. These exact saved-row counts were independently counted by `scripts/verify_v03_evidence.py`.

Cooperative003 chooses local-search initialization from completed classical baselines only. If none completed, local search also returns a no-coverage row; no generated-program fallback is substituted. It uses a cooperative guard checked every 256 charged-work meter writes instead of the initial SIGPROF guard. The scope remains a five-process-CPU-second execution target with possible primitive/cleanup overshoot, reported using measured CPU times; it is not a hardware-real-time deadline. Program ASTs, rankings and selection are unchanged. All failed harness snapshots are retained.

A later trace identifies why the first bounded primary harness did not finish: its local-search initialization took the maximum over baseline rows that mixed completed numeric values and timeout values of `None`. Python raised `TypeError` after workers drained. This is an initialization bug, not evidence of a failed signal delivery. The cooperative snapshot filters to completed classical initializations; if none complete, local search records no returned schedule and no fallback. Both failed snapshots and their task denominators are retained.

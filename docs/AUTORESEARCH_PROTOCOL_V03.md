# Scientific autoresearch workflow

Applied local autoresearch skill v2.2.2 (classic mode) and research-paper-writing skill v1.1.0. Upstream references: https://github.com/karpathy/autoresearch and https://github.com/uditgoenka/autoresearch . Their fixed-budget experiment/evidence/keep-or-discard loop is adapted to a scheduling research study; a GPU nanochat training loop is not claimed to have been executed.

Each hypothesis has an immutable source snapshot and measured artifact; substantive changes are retained only with a scoped reason. Negative findings stay in the ledger. Shared agent edits are not reverted automatically; immutable candidate archives and source receipts provide the scientific equivalent of keep/discard checkpoints. The v03 guided/free/rule banks are independent assistant responses; the twelve new v04 proposals come from one continuing offline assistant session with parent feedback before v04 TRAIN outcomes. Authoring counts and checking compute are unequal.

The original v03 study uses TRAIN evidence and validation quality/work followed by a pre-test freeze. The v04 numerical selection uses TRAIN only: its 132 fresh validation and 456 test contexts do not select programmes. Qualitative v03 failures motivated the new study, so it is not claimed blinded to that motivation. There is no automated mutation against a fresh test metric. Later fixed-AST execution and reached-action extensions retain their own protocols, budget/source versions and evidence; their outcomes do not change the published TRAIN selection or replace the original confirmation.

The ledger is autoresearch/loop-261003-v03/results.tsv. It separates certificate soundness, information adequacy, scoring consistency, full-schedule quality, and actual computation. A single convenient scalar does not justify conflating those claims. Cloud host operations, failed environment setup, detailed budgets/prompts and logs belong in Markdown/evidence supplements; they are not paper narrative.

This is an applied workflow, not a claim that upstream skills guarantee acceptance or that all suggested external integrations were installed. The manuscript uses official AAMAS formatting, published sources only, independent section writers, independent formal review, and final number/page/visual audits.

The v04 principal TRAIN/fresh/public comparison is complete and independently audited; its negative comparison to published MWIS implementations is retained. Acyclic declared interfaces are not numerical perfect-fit gates: the primary agrees with 631/824 saved TRAIN orders. Pure component cancellation narrows 199/396 matched intervals without increasing strict yield. Detailed decisions are in ledger rows 10--13. The fixed-action extension passes 330,923 checks; its primary has 18 positive, 191 zero and 346 unresolved sampled test-state finite-pool regrets. The separate thirty-second sparse execution extension passes 123,726 checks but still has no assessable full-scan/heap pair; increased completion does not establish paired acceleration or backend parity. These outcomes change no selection or original-budget result. Final release tests, page/figure verification, source-portability checks and Git publication are separate engineering handoff items, not paper-level scientific outcomes.

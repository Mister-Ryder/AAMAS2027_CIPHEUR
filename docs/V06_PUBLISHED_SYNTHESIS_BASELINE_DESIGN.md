# Published synthesis comparator: outcome-free design

**Recommend a separate `EoH-DSL (shared R1 warm seed, 8-candidate)` discovery pipeline.** It must perform genuine offline LLM calls, population selection and all five published discovery operators. It is a task/budget adaptation of EoH, not native EoH reproduction, the R2 objective-only arm renamed, or a claim of effectiveness. This document and its prototype precede additional authoring/results; root must separately review and release them. No R2 response/candidate outcome or genuine TEST label was read, and no real authoring/evaluation was executed. Existing R1/R2 samples, gates, selectors, kernel and release remain untouched.

## What the formal methods actually do

**EoH, ICML 2024.** An individual contains a natural-language thought, executable heuristic and measured fitness. Population search uses E1 (different ideas), E2 (new ideas from shared parent structure), M1 (modify a parent), M2 (change parameters) and M3 (simplify redundant components), followed by fitness-based retention. The paper generates N initial individuals and N offspring per operator; its main experiments use 20 generations and populations of 10 or 20. This is substantially larger than our proposed cap. [Formal PMLR record](https://proceedings.mlr.press/v235/liu24bs.html), [formal paper, §§3.2–3.4 and §4.1](https://raw.githubusercontent.com/mlresearch/v235/main/assets/liu24bs/liu24bs.pdf).

The inspected official legacy tag `v0.1` resolves to **`4b2338fc2317c743cec50c5c7a2e4684707af973`**. Its operator module implements all five strategies, although default parameters activate only E1/E2/M1/M2. The EC wrapper supports seed populations, evaluates offspring, rounds fitness to five decimals and may issue extra parse/duplicate retries. Rank sampling is with replacement; population management removes equal-objective individuals. These details must be disclosed when adapting the controller. [Operator prompts](https://github.com/FeiLiu36/EoH/blob/4b2338fc2317c743cec50c5c7a2e4684707af973/eoh/src/eoh/methods/eoh/eoh_evolution.py), [EC wrapper](https://github.com/FeiLiu36/EoH/blob/4b2338fc2317c743cec50c5c7a2e4684707af973/eoh/src/eoh/methods/eoh/eoh_interface_EC.py), [defaults](https://github.com/FeiLiu36/EoH/blob/4b2338fc2317c743cec50c5c7a2e4684707af973/eoh/src/eoh/utils/getParas.py), [rank selection](https://github.com/FeiLiu36/EoH/blob/4b2338fc2317c743cec50c5c7a2e4684707af973/eoh/src/eoh/methods/selection/prob_rank.py), [population management](https://github.com/FeiLiu36/EoH/blob/4b2338fc2317c743cec50c5c7a2e4684707af973/eoh/src/eoh/methods/management/pop_greedy.py).

**ReEvo, NeurIPS 2024.** Each iteration selects successful parents of unequal objective value, asks an LLM for short-term comparative reflection, generates crossover offspring, summarizes accumulated reflections with another LLM call, then mutates the elite. Offspring are evaluated after crossover and mutation. Optional seeds are allowed. Its reported defaults are population 10, initial generation 30, maximum 100 evaluations and mutation rate 0.5. The official controller rejects equal-objective parent pairs and can terminate when selection fails; it also checks its evaluation cap outside whole batches. Thus a faithful small-budget implementation must account for reflection calls, pair availability and batch overshoot, rather than silently inventing better/worse comparisons or dropping reflection. [Formal proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/4ced59d480e07d290b6f29fc8798f195-Abstract-Conference.html), [formal paper §4 and Appendix C, Table 8](https://proceedings.neurips.cc/paper_files/paper/2024/file/4ced59d480e07d290b6f29fc8798f195-Paper-Conference.pdf), [official controller at inspected commit `6dce18257da5e11db2d138e417a2fffc5c72d05f`](https://github.com/ai4co/reevo/blob/6dce18257da5e11db2d138e417a2fffc5c72d05f/reevo.py).

EoH is the recommended first implementation because all five operators fit a strict eight-candidate adaptation without extra critic calls or a requirement for unequal rewards. This is a feasibility judgement; future quality plateaus or gains are unknown. ReEvo remains a distinct possible later comparator requiring its own pre-outcome reflection/candidate budget, not an interchangeable name for EoH or objective-only generation.

## Proposed fixed protocol

| Item | Commitment before any new call |
|---|---|
| Namespace/role | Separate published-comparator discovery and result namespace; quality-only policy discovery, not a jointly certified proposed winner |
| Authoring runs | Four fixed independent runs, IDs 0–3; never choose the best four from additional runs or replace a failed run |
| Candidate cap | Eight original candidate attempts/run, at most 32 total; invalid syntax, duplicate outputs and transport failures consume their positions |
| Initial parent | Exact R1 warm seed shared with R2, with its TRAIN-label-selected history disclosed; four initial 120-state evaluations are separately charged/reported |
| Population | At most two distinct rounded quality-objective values, retaining the first current-population identity at equal objective; the warm seed is an ordinary initial member |
| Slot order | `i1, i1, E1, E2, M1, M2, M3, E2`; exactly one candidate requested per genuine call; no hidden parse/duplicate/quality retry or extra reflection call |
| Discovery interface | Identical frozen `FeatureRuleProgram` feature-tree/rule grammar, library and priority hook; E1/E2/M1 may jointly change features and rule, M2 changes numerical parameters, M3 simplifies |
| Fitness | All original 120 TRAIN states, original F/X and complete shared-kernel schedules; official minimization scalar `numpy.round(-float(exact equal-family reward/total graph weight),5)`; equal values retain the first current-population identity |
| Work | Exact equal-family feature-plus-repair work is feedback and reporting only; it never breaks a fitness tie or changes parent/winner selection |
| Feasibility/validity | Existing static grammar validation and finite actual scored execution; exactly 120 completed-feasible error-free kernel rows for fitness eligibility; ordinary cap stops retain their feasible incumbents |
| Feedback | Parent thought/program, complete-schedule quality/work, equal-family summaries and failure statuses; fixed task/grammar and objective-only common TRAIN context |
| Forbidden discovery feedback | Conditional labels/intervals, strict-fit values, quotient gates/cycles, equality joins, witness examples, R2 frontier/seed diagnosis, any TEST input or performance; the shared code itself retains its disclosed TRAIN-selected history |
| Parent RNG | Separate stream per original run/slot from SHA256(`V06_EOH_DSL_PUBLISHED_001\|run_id\|slot\|parents`); freeze the conversion/RNG implementation and actual drawn parent IDs |
| Deployment | Best completed-feasible terminal-population member/run, including a warm seed that remains best; four nonguarded quality identities, absent when the run fails; no invented authored replacement |

Rank parents with the declared quality-only ordering and sample with replacement using weight proportional to `1/(one_based_rank + current_population_size)`, as in the inspected official selector. E1/E2 draw two parents, M1/M2/M3 one. A one-member population may yield repeated parent references; declare this rather than requesting extra candidates. Update population after each slot, preserving official equal-objective collapse even for different ASTs or different work costs. Keep every raw position in the ledger. If all quality values tie, the seed may remain the sole incumbent. If it cannot complete its original feasibility contract, record the run as aborted and all unissued positions as missing, without another seed. No quality improvement is assumed.

Only TRAIN problem states are available to the evaluator. Build an immutable author context from the original objective-only task/grammar and metadata-selected TRAIN examples, stripping all conditional queries, aliases, quota labels and certified feedback. Do not call `assess_candidate`, whose information assessment reads TRAIN certificates, during discovery. A separate quality adapter must invoke the unchanged compiled priority/runtime and `repair_schedule`, verify full-graph reward/feasibility, and calculate the same `macro_quality` quantities. Post-freeze certificate diagnostics may be reported later, but never select parents or winners with them.

## Fidelity, budget and interpretation limits

**Retained:** thought-plus-program individuals, actual measured schedule fitness, rank-selected parents, exploratory/recombination prompts, three modification operators, elite population retention and real sequential LLM discovery. Parent programmes and evaluated feedback feed later calls; this makes the pipeline different from the single R2 objective-only batch.

**Adapted:** MWIS task, identical frozen 6/48/8 typed feature-tree/rule output instead of unrestricted Python; one offspring/operator instead of N; the small fixed sequence/population; shared R1 warm seed; explicit complete-schedule quality/work annotations; bounded one-call attempts instead of upstream retries. Official five-decimal quality-objective deduplication and with-replacement rank sampling are retained. The adaptations must appear in the comparator name/method description; they do not reproduce published hyperparameters or unrestricted heuristic expressivity.

The matched R2 cohort has eight slots/cell and four retained blocks (32 slots per arm), but its complete study has five original blocks (40 slots per arm). This baseline has four **fixed** runs, not R2's transport-selected cohort. Its eight sequential calls/run also differ from R2's one call requesting eight candidates; equal candidate caps do not equal token, model-call or discovery-time budgets. Report all 32 attempt identities, actual transport/candidate counts and the R2 40-position denominator separately. Four authoring draws are descriptive, and must not be treated as paired randomized R2 blocks.

The comparator and R2 use the same R1 warm seed, whose prior selection used TRAIN labels and gate/fit evidence. Authors see the shared code and quality feedback, but no new certified labels or diagnosis. This is conditional same-start pipeline discovery, not an independent cold experiment or label-free complete history. R2 also received its registered frontier/feedback and uses different selection roles; four separate baseline runs do not identify an isolated causal witness or model-population effect. R2's existing objective-only samples remain unchanged.

A retained seed uses `winner_origin=shared_R1_warm_seed` and is not a new LLM-authored success. Every generated candidate still needs its genuine native CLI receipt. Slot failures have absent measured quality/work, with unexecuted state counts distinguished from actual kernel errors. Full original `f640` TRAIN information-gate/fit diagnostics may be applied after every original author position is frozen, but never affect population or winner selection.

## Implemented prototype and transaction boundary

New files are `cipheur/published_eoh_v06.py`, `scripts/author_published_eoh_cli_v06.py`, `configs/published_eoh_v06_001.json` and `tests/test_published_eoh_v06.py`. `prepare` accepts only a 120-record TRAIN-only problem artifact (id/split/family/cluster/graph/digest/F/X), an objective-only common context with the exact exported grammar, the shared seed binding, kernel config and native-transport binding. It rejects certificate/query/gate fields. The seed binding requires program/source hashes, source candidate ID, `TRAIN_label_selected_history=true` and the R1 seed-selection receipt byte hash. No actual preparation has been performed; tests use fabricated graphs/metadata.

After root review, save `root_authoring_release.json` in that new study with version `v06_published_EoH_root_authoring_release_001`, `issued_by=root`, `allow_authoring=true`, the study protocol/freeze receipt byte hashes, `shared_R1_warm_seed_sha256`, `R1_seed_selection_sha256`, `requested_positions=32`, and `TEST_allowed=false`. Every action requires its explicit byte SHA256. Native configuration and executable must match the supplied frozen transport binding.

The intended manual sequence is:

1. `request --run B` creates an immutable seed-evaluation request; copy the source/input/request capsule through root's existing secure SSH connection. Root or the effect executor invokes server-only `evaluate`, which writes full observations plus a strict quality/work/error feedback object. No certificate assessor is called and no certificate file is loaded.
2. Copy the result capsule back through that trusted connection and `ingest` it with the explicit server feedback byte hash. The local controller validates source/input/request/result bindings and rechecks imported feedback hashes before later use.
3. `request --run B --slot S` derives the fixed operator and parent draw from prior imported fitness. `author_published_eoh_cli_v06.py` rebuilds that recipe, then makes exactly one fresh read-only native call. It retains original input, last message, events, stderr, usage/model metadata and failed transports; no hidden retry.
4. Transfer request and raw call capsule to the server, `evaluate` all120 TRAIN schedules, and manually `ingest` its bound filtered feedback. Repeat original slots0–7 in order for fixed runs0–3. The local driver performs no SSH or fitness evaluation and reads no credentials.
5. `finish` freezes all32 position dispositions and four terminal quality-baseline identities. A failed seed run has null output and explicitly unissued positions. Full gate/fit examination, independent native-event review and a future performance/TEST release remain separate later steps.

Use the modules' `--help` for exact path/hash arguments. Nine outcome-free tests cover official equal-quality degeneracy/work exclusion, repeated parent draws, immutable grammar/operator budget, two actual tiny TRAIN kernel states, source/root-release checks before any CLI spawn, dependent request ordering, feedback/parent tamper checks, invalid attempts without invented measurements, seed/null final roles, and rejection of TEST/certified fields. No actual native author call, R2 result or genuine TEST frame is accessed by these tests.

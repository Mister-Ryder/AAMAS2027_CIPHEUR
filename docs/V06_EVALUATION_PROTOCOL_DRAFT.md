# V06 framework-contribution and shared-kernel evaluation draft

Date: 2026-10-03. Independent design review, before V06 authoring and TEST outcomes. This is a proposed synthesis/performance protocol, not an experiment result or an acceptance prediction. The evidence inventory was subsequently frozen as `experiments/discovery/v06_evidence_001`; the actual counts and budget scope below reflect that pre-query freeze. The controller must resolve the remaining synthesis/performance choices and save a machine-readable protocol, input inventory and source capsule before execution. V04/V05 programs, archives, unsuccessful cases and conclusions remain immutable.

## Scientific objective and recommended implementation

The V05 greedy selector does not support a claim of competitive MWIS performance: specialized published methods dominate its small scheduling populations, and the new matched authoring pilot found a small label-feedback effect but almost no witness-over-label effect. Changing the normalization or ordering the tables cannot establish a new advantage.

Keep the accepted innovation: sound offline conditional decision evidence diagnoses conflicting rankings under an insufficient representation; structural witnesses guide joint feature–rule refinement subject to computation cost. Replace the weak execution backend with a **shared incumbent-preserving local-repair kernel**. Every framework arm receives exactly the same kernel, initializer, feasible-move set, budgets, tie ordering and fallback. The frozen synthesized program changes priority; it does not establish feasibility or upper-bound correctness. Mature local improvement, reductions and exact search are credited to their published sources.

**Recommended first path:** deterministic shared patch construction plus synthesized local feasible-greedy ordering and pivot-vertex priority inside bounded MWIS repair. This isolates the effect of representation and rule synthesis on a common search problem. All groups start from the same Degree incumbent. Keep patch-construction rules deterministic and identical; conditional on the same incumbent their patches agree, while later trajectories may diverge after different valid improvements. Program score is evaluated on the actual patch snapshot and chooses the next pivot; include-first/exclude-second traversal is shared across all arms. Scores never prune a feasible branch. This matches the current shared structural repair module.

**Second path, only as a separately frozen extension:** synthesized structural priorities select patch anchors or allocate a fixed total search budget across a common operator catalogue. All arms must have identical anchor eligibility, catalogue and total budget. This could test adaptation to constraints more directly, but adds a second decision interface and substantially more attribution risk. Do not simultaneously change patch size, pruning, restart count and feature library in the main witness contrast.

The [formal CHILS paper](https://drops.dagstuhl.de/storage/00lipics/lipics-vol338-sea2025/html/LIPIcs.SEA.2025.22/LIPIcs.SEA.2025.22.html) already studies local search and cooperation between solutions. Those operations are prior art. Its [official implementation](https://github.com/KarlsruheMIS/CHILS) supplies an initial-solution interface and a library API. An instrumented shared component must be described as such, while the unmodified executable remains a distinct published comparator. Importing a stronger component cannot itself prove a framework or LLM contribution.

## Kernel semantics and guarantee boundaries

Let I be a verified feasible incumbent respecting permanent commitments F and exclusions X. Select D ⊆ I with D ∩ F = ∅, keep Fout = I ∖ D, and define R = V ∖ (Fout ∪ N(Fout) ∪ X). The restricted patch R' must satisfy D ⊆ R' ⊆ R. Consequently D is a feasible patch incumbent. For any independent J ⊆ R', the replacement Fout ∪ J is globally feasible and preserves permanent commitments.

A verified clique partition of R' gives a sound upper bound U(R'). If U(R') ≤ w(D), skipping the patch proves **no strict improvement inside that restricted patch only**. It proves neither that the larger neighborhood has no improvement nor that I is globally optimal. Bounded search starts from D, stores every independently checked feasible improving J, and on time/work/node cap returns its best already known solution. Commit only strictly positive gain under the registered numerical convention and recheck original graph feasibility. A capped repair with a valid incumbent is an interrupted search, not zero-quality algorithm failure.

Pruning ON/OFF controls share patch construction, score order, initial D and limits. Specify exactly which sound optimization bound is disabled. They never disable feasibility checks. Reductions require solution reconstruction and original-graph verification. No branch score or floating MILP dual value is accepted as a certificate.

The abstract's fixed feasibility-enforcing kernel can accommodate local repair; the V05 manuscript's irreversible greedy-commit description cannot. Rewrite that execution definition when implementation changes. Offline labels still use explicit, immutable F/X; temporary patch commitments are not permission to retract an offline boundary.

**Evidence-to-execution scope:** a conditional preference certified on a full residual graph is not automatically a preference inside R'. Measure its rule fit on the exact certified snapshot. Measure repair quality and cost on actual execution patches separately. If a TRAIN-only extension queries patch labels, express the patch as an explicit boundary, fixing Fout and excluding vertices outside the permitted patch, and certify on that exact state. In paired interventions the boundary must be feasible on both sides; otherwise record the boundary failure. The online bounded repair search is a classical solver component; it is separate from the offline conditional certification oracle and must be described honestly rather than hidden under “no oracle.” There are no online LLM calls or online calls to the certification interface.

## New evidence inventory and leakage control

The controller's proposed evidence has two separately reported tracks:

1. **Public source-derived states.** Use the already archived original public graph corpus, group by original source graph identity and sort within each family by the declared salted SHA ordering. The frozen split is nine DIMACS and 15 SATLIB sources per side: 24 TRAIN and 24 held-out states. Derive new 32-node induced states using salt `v06_261003_new_source_state_queries_001`. Freeze original source hashes, orientation, vertex identities, induced-state digests and derivation code before querying. This is source-disjoint evaluation of new states and new labels **inside a previously exposed benchmark corpus**. It is not evaluation on a wholly unseen corpus. Old two full-graph counterexamples are known DEV repair checks, not new independent TEST evidence.
2. **Controlled synthetic physical states.** The frozen generator creates valid 32-contact pairs with unit reward, duration one, three constraint regimes and horizons 11/24. Resource counts are balanced (eight satellites/six stations), ground-scarce (12/three) and satellite-scarce (three/12), with start times on quarter-unit increments. There are eight TRAIN source seeds and four TEST source seeds per regime/horizon: 48 TRAIN pairs/96 endpoints and 24 TEST pairs/48 endpoints. The only intervention parameter is station gap, zero→one in TRAIN and 0.25→two in TEST; the latter tests a held-out configuration shift. Freeze the exact generator, source seed namespace, resource assignments, timeline construction, hard conflict predicate and pairing before oracle queries. These are controlled satellite-like synthetic cases, not empirical evidence of natural C3 incidence.

The saved inventory contains **192 states: 120 TRAIN and 72 TEST**, with 2,465 total scheduled competitor queries across both splits, all at empty F/X. Data SHA256 is `968f96b7712ca3ecc8a7b43f567c6b6403742f26f0e76e9d5f2c680973827784`; protocol SHA256 is `32e008c2d348df53813696f8bfc413829704a9e76c07e4d03ac036387cb11854`. The preparation source asserts all state digests unique and no TRAIN/TEST graph-digest overlap. These preparation counts are not evidence outcomes.

For each state, order eligible equal-nine-base-feature competing edges deterministically and retain at most eight. Add at most eight nonalias controls with an independently specified hash order. Competitors must remain individually feasible under the same explicit boundary; avoid pairs whose labels merely change because one action became infeasible. Keep every scheduled query slot: strict label, exact conditional-value tie, interval-unknown, boundary failure, unavailable slot or unqueried due to budget. Do not replace a tie/unknown with another pair. Reversal and strict-preservation specifications require strict certified signs on both endpoints; one known and one unknown is incomplete evidence. An exact tie in optimal completion values does not automatically require equal heuristic scores.

**Resolved pre-execution budget scope:** the append-only `BUDGET_SCOPE.json` states that a new oracle instance is created per graph/state snapshot. Each state shares a 1,024-call/two-million-expanded-node cap across its own prescheduled queries. Each unmatched component has a 50,000-node search ceiling and a 32-vertex search cutoff; bound caches are shared within that state. Identical cancelled components do not consume component solver calls. There is no global cap, so public ordering cannot starve the synthetic states. Keep the original freeze unchanged and bind the clarification's exact bytes in execution/source receipts and audits. The actual constructor/difference implementation must be audited against these meanings; two competing actions are not necessarily two component solver calls.

All TEST queries and their labels are withheld until the entire candidate inventory, raw-slot status and TRAIN-selected winners are frozen. Do not disclose TEST graph snapshots to authors. Do not revise ASTs, library, rank tolerances, weights, patch settings or selector after TEST results. Existing 200 unresolved physical queries remain unknown. New bounded oracle failures do not become ties or evidence against a hypothesis. Synthetic prior graph motifs remain a separate diagnostic track and cannot supply a natural-incidence headline.

## Matched synthesis arms and authoring freeze

Use four independent authoring blocks, three arms and eight raw proposal slots per block/arm: **96 planned slots**. Each block contains three fresh cold sessions with the same requested model, reasoning setting, tool restrictions, graph library, feature/rule limits and number of slots. Match proposal opportunities and session settings; observed token use, backend identity and latency are separately measured rather than claimed equal.

| Arm | Authoring information | Shared evaluation and selection |
|---|---|---|
| A: witness-guided | Common TRAIN snapshots, quality feedback and certified relational labels; explicit quotient conflicts, structural witnesses and feature joins | Same strict-label scoring, interface gate, kernel, objective/cost evaluator and selector |
| B: relations-only | Exactly the same graph snapshots, quality feedback and relational labels, without supplied conflict joins/witness explanations | Same as A; authors may discover structures themselves using the same library |
| C: objective-only | Same graph snapshots and objective feedback, without supplied relational labels or joins | Same hidden TRAIN evaluator and selector; this contrast measures authoring feedback, not absence of supervision anywhere in the pipeline |

Bound packet size by a deterministic, stratum-balanced subset chosen before new outcomes; full evidence remains the shared selection/audit set. Do not choose visually favorable examples by candidate quality. Do not include old banks, failed selected programs, paper outcomes or TEST data in cold sessions. Save raw responses, prompts, transport receipts and requested settings. Missing, invalid and duplicate slots remain in their original positions. There is no validation repair, replacement call, arm-specific hand-added feature or silent fallback candidate. Duplicate programs are still repeated slots, not independent new mechanisms.

Controls now frozen in `experiments/discovery/v06_controls_001/control_banks.json` include a fixed Degree priority, eight deterministic structural templates and eight fixed-interface base-nine expressions. Structural templates enumerate catalogue sizes two/three/four/six and coefficient blends 0.25/0.75; they receive the **same number of assessed slots per bank and common interface/kernel caps**. They are assessed-slot-matched enumeration, not random generation or equal model/token compute. Repeating the same ASTs across four blocks measures execution variability and does not create independent authoring draws. The controller wrote templates after TRAIN evidence auditing without evaluating any control feature, fit or kernel outcome, and read no raw new model response; this is not a claim of blind human/non-AI provenance. Fixed-interface impossibility on exact alias relations establishes an information limitation by construction; it is not evidence that an LLM is better than a non-LLM generator. A/B both access the same expanded library, so their difference tests the value of explicit witnesses. Do not call unmatched large hand banks fair.

Forbid source IDs, graph hashes, benchmark names, seed values, label lookup tables, conditional-optimum calls and hidden oracle outputs in program semantics. Features use only current graph/state data and the registered typed library. The information-equivalence definition must match that declared interface and pinned numerical semantics. Approximate “nearly equal” vectors cannot be used as exact impossibility witnesses.

## TRAIN scoring and frozen joint selector

Store separately for every raw slot: parsing/type validity, actual-only quotient obstruction count, prior-motif obstruction count, number of retained certified strict requirements, numerical strict agreement, complete-schedule/repair quality, feature work, search work and measured time. A quotient DAG permits an unrestricted scalar ordering of the observed equivalence classes; it does not prove that the bounded DSL rule fits them. A representation that distinguishes all pairs can still have a wrong score. The current interface assessment computes full declared features for a separate declared diagnostic, even when those features are unused in the rule; that computation consumes the common offline assessment cap. Distinguish its cost from score-sliced deployed feature work.

Freeze the selector lexicographically or through an explicit utility formula, including failure handling and numerical tolerances. One defensible lexicographic contract is: valid interface and feasible execution; highest certified strict agreement; highest mean shared-kernel TRAIN reward; lowest registered feature-plus-search work; deterministic slot-index tie break. If an all-relations fit gate is used, declare the fallback when no candidate passes. Do not relabel partial fit as consistency or weaken the gate after seeing zero eligible programs. The same policy applies to all arms, and the resulting eight-prefix learning curve must retain missing prefixes when no eligible candidate yet exists.

Record standalone feature-catalogue cost separately from actual shared-cache execution cost. A finite additive-cost representation theorem does not establish minimum runtime cost for the implemented LLM bank. Offline certificate-generation cost is disclosed once for the shared dataset; arm-specific supplied reasoning and model costs are counted separately.

## Executable first-table metrics

The first table should expose the framework mechanism, with TRAIN and withheld-label TEST columns, raw denominators and four-block descriptive contrasts. No outcome is assumed favorable in advance.

| Metric | Definition and denominator | Legitimate interpretation |
|---|---|---|
| Evidence coverage | Strict / exact conditional tie / queried unknown / unqueried / unavailable over all frozen query slots, by track | How much sound decision evidence exists; no LLM benefit |
| Actual obstruction repair yield | Valid raw slots with an acyclic quotient on actual strict requirements / all eight slots per block | Expanded interface removed detected contradictions; keep prior motifs separate |
| Scalar strict fit | Number of certified strict inequalities obeyed by the actual scorer / all known strict requirements, with zero for invalid raw slots in unconditional yield and a separate selected-rule score | Rule fit beyond representation feasibility |
| Held-out reversal/preservation fit | Correct paired requirements / all fully certified paired requirements; incomplete endpoints retained outside this known-only denominator | Constraint adaptation on withheld labels under explicit boundaries |
| First usable repair | Original slot index and assessed feature/search work until the first valid declared-fit candidate; no success is censored as “not observed” with all eight attempts charged | Proposal efficiency, if A beats B on actual evidence |
| Cost | Feature operations, search nodes, original CPU/wall, input/output/cached-token receipts and session latency, each stated separately | Actual resource effects; slots/settings matching is not compute matching |
| Shared-kernel improvement | Exact reward gain over the common initializer at the frozen budget, plus completed patches/nodes/improvements and full incumbent coverage | End-to-end benefit of frozen priority under a common kernel |

Report both pooled counts and block means. Four blocks do not establish a broad model-population effect. Bootstrap/test-instance uncertainty does not replace uncertainty from four authoring draws. Source-derived unit/hash variants and intervention sides are clustered by original graph or source contact realization, not treated as independent datasets. Predeclare primary A−B and secondary B−C contrasts, and do not select the more favorable arm pair after evaluation.

An advantage can be supported only when new actual evidence yields a meaningful A−B difference in fit/yield/work or transfer under the shared kernel. Better A/B than fixed-interface rules alone supports representation expansion, not unique LLM value. If A and B tie again, retain that null result and revise the claim rather than inflate chart scale. Improving the two already known public counterexamples demonstrates a repair example only; it is not independent generalization.

## Hard performance population and published baselines

Freeze a separate performance inventory selected by provenance and metadata, not by our eventual wins. Proposed synthetic scheduling sizes are 512, 1024 and 2048 contacts, across the same three resource-regime families and a declared sparse/dense horizon construction. A feasible bounded scope is six new source pairs per size/regime/family: 108 pairs, 216 endpoints. Use disjoint TRAIN generation and TEST seed namespaces and freeze all source IDs before any solver outcome. TRAIN-only hardness pilots may adjust horizon/resource scales **before** the final generator freeze; no TEST graph is dropped because it is easy, hard or unfavorable. Small 32/64/128/256 cases remain correctness and certificate diagnostics rather than the main competitiveness evidence.

For public hard cases, first inventory official raw files not previously used by V04/V05 and split source families before running. The [CP 2017 author benchmark repository](https://github.com/jamestrimble/max-weight-clique-instances) offers several weighted application families. Its README explicitly identifies UAI files as MWIS, whereas other collections are maximum-weight-clique files. Preserve that orientation: complement clique instances only when converting them to MWIS, with an exact original-objective identity check. Pin archive and graph hashes, family, original weights and any conversion. Native weighted data are preferable to treating hash-generated weights as a real application dataset. If resource limits prevent using additional raw data, label the reused benchmark transfer exploratory; do not call it unseen public data.

Retain complete performance rows for CHILS, its one-state ILS control, M2WIS, Struction, WeightedBR, the shared strong kernel with Degree, A/B/C winners and the fixed-interface/non-LLM controls. Cite each published method immediately in the table. Do not hide a mature solver because it wins. A component-modified shared kernel is not an unmodified reproduction of that method. Same-library controls address attribution; published solvers address practical competitiveness.

Choose one primary deadline convention before execution. Recommended primary: **one-core end-to-end wall checkpoints of 1, 5 and 30 seconds**, including input preparation, initialization, feature computation, patch construction, search and decoding. Isolate benchmark workers from competing CPU load and record CPU time as well. Use five fixed stochastic seeds for stochastic solvers; repeat deterministic programs only for timing variability and identify them as repeats. Hard deadlines require checkpointed incumbent output; preserve the verified shared initializer on an interrupted shared-kernel search. If an unchanged native solver cannot expose a valid incumbent by a hard stop, report missing incumbent/coverage explicitly. Do not fabricate its timeout objective, replace it with our initializer or treat its documented internal five-second target plus a 30-second external guard as a matched five-second deadline.

If exact hard-deadline harvesting is not implementable, use an honestly named nominal solver-time track with original elapsed CPU/wall and violations, and a separate common deterministic-work track for shared-kernel arms. These are different comparisons. Do not mix them in a “same time” superiority claim. Validate integer scaling exactly, retain overflow/unsupported-input failures, pin binaries/source/compiler/options, and keep all native scores subject to original-graph feasibility checks.

Report raw objective and paired relative reward difference against each named published method at each budget, with solved/valid-incumbent coverage. A frozen independently verified upper bound U can supply an additional gap column; a pre-run feasible lower bound L is not an optimum or upper bound. Do not update the denominator to a new best method and hide saturation. Include common-initializer gain and anytime curves, plus win/tie/loss and source-cluster uncertainty. Cost per accepted improvement or reward-gain curves can reveal a framework benefit even when a native method has better final quality, but cannot support overall SOTA claims.

## Freeze and stop rules

The controller should freeze, in order: (1) input inventory and complete query order/budgets; (2) TRAIN evidence with independent certificate replay; (3) shared kernel and typed library plus small exact correctness checks; (4) authoring protocol and packets; (5) all 96 raw slots and assessment source; (6) TRAIN winners and selector receipt; (7) withheld-label and hard-instance evaluation commands. TEST labels are queried only after stage six. Every amendment is dated and distinguishes before-outcome from after-outcome changes.

Independent checks should replay source derivation, alias equality, individual feasibility, interval bounds/cancellation, query coverage, all raw-slot status, winner identity, original-graph reward and monotonic incumbent trace. Small exact repair tests establish restricted-patch optimum and no degradation on cap; they do not test the empirical paper hypothesis. Bind raw archives, source capsules, authoring receipts and audit hashes before manuscript results are updated.

If new evidence provides few strict labels, report that coverage limitation and keep the intervention design transparent. If no candidate repairs numerical fit, there is no repaired-rule result. If all strong-kernel arms solve the hard population equally, there is no quality advantage; examine predeclared work/cost contrasts without inventing new favorable subsets. Further source acquisition or methods form a new registered round, leaving this round intact. No experiment can guarantee acceptance.

## Claims currently prohibited

- “LLM-guided synthesis outperforms advanced MWIS algorithms” without a fair new performance result.
- “Witnesses improve synthesis” from fixed-interface impossibility, prior-motif yield alone or A/B ties.
- “Natural physical aliases were discovered” from engineered unit-duration cases, source-derived public graphs or the unresolved C3 queries.
- “An acyclic quotient certifies our program” without numerical rule fit.
- “No oracle at inference” if online exact repair is left undescribed; distinguish the absent certification oracle from the classical bounded solver.
- “Minimum feature runtime” from an additive standalone-catalogue theorem or greedy/LLM selection.
- “Equal compute” from equal slots and requested model settings.
- “Same five-second budget” for cooperative caps with different uncharged setup/overshoot or native five-second targets with 30-second external guards.
- “Source-unseen public test” for the previously exposed V04 corpus.
- “Global optimum/no remaining repair” from a restricted patch upper bound.

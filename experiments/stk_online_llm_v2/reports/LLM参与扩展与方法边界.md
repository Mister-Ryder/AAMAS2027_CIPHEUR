# LLM参与扩展与方法边界

本报告解释online v2中LLM的真实职责、与既有工作的关系，以及本轮证据能够支持的结论。它不代替实验结果报告，也不把工程完成状态写成算法优势。固定运行条件见[实验协议](../PROTOCOL.md)，代码与证据导航见[README](../README.md)。

## 1. 本轮解决的是哪一个问题

前期诊断显示，修复“信息不足”并不会自动带来正确排序，更不会保证完整调度收益。如果仅生成一个评分表达式，再从历史TRAIN成绩选出胜出表达式并固定部署，表示、搜索政策和实际当前实例之间的联系仍然薄弱。本轮因此改为：LLM提供可复用的语义配方与演化模板，实际优化在**当前完整实例内部**完成，更新结构特征、规则、系数及局部搜索政策。

LLM使用历史TRAIN失败反馈生成初始化是允许的离线设计工作。运行时没有读取历史胜出分数表来指定当前策略；所有候选收益与信用更新都来自当前实例。固定的是可复现的源码、银行和实验条件，每次运行的种群与学习状态均重置。

算法面向同一物理可见窗口在地面资源间隔改变后形成的不同冲突图。当前评估将每种静态配置作为完整问题冷启动重新求解，尚未实现warm传递、求解中途约束事件或任务到达。不能把静态跨配置比较描述成已经实现的实时动态调度。

## 2. 为什么这里使用LLM

一个条件证书只能告诉算法哪些相对决策有可靠要求，不能直接写出计算成本合适、可泛化的结构表达式。Witness描述缺失区别的位置及连接方式，失败曲线又指出搜索、成本或拒绝方面的瓶颈。把这些异质证据翻译为合法图操作、可执行排序规则和搜索政策，是LLM可以承担的语义合成任务。

例如，在边界承诺明确的两种资源配置中，若可验证的条件完成值界认证同一对根节点需要相反的排序，而当前特征向量却完全一致，则任何只依赖该向量的确定性评分函数都无法同时满足这两个严格要求。这给出了表示不足的数学理由。它没有证明LLM是唯一选择：人工设计、枚举语法、程序搜索同样可能找到区别。LLM的待验证价值在于利用结构语义与失败上下文缩小搜索、提出有用的可执行配方，而非代替数值证据。

职责分工如下：

| 环节 | LLM或运行组件的职责 | 本轮不能直接推出的结论 |
| --- | --- | --- |
| 结构证据解释 | LLM将真实见证转译为typed特征和规则候选 | 有区分能力不等于正确排序 |
| 失败反馈解释 | LLM根据TRAIN完整质量、曲线与成本提出政策/演化模板 | 推断瓶颈不等于已克服瓶颈 |
| 数学证书 | 可信计算在明确边界承诺下给出条件值界 | 局部证书不是全局最优性证明 |
| 当前实例适应 | 控制器演化候选，按当前收益/成本更新信用 | 更新次数不等于收益 |
| 完整结果接受 | 内核检查全图可行性和实际完整增益 | 局部排序改善不等于完整收益 |

正式求解没有在线LLM调用。当前实例内的条件计算属于搜索工作，计入同一预算；这与离线提前求解TEST再部署其答案不同。利用TEST汇总结果修改银行、方法或预算不允许，但在当前TEST实例上根据目标值进行启发式/进化搜索是求解器的正常运行过程。

## 3. 真实调用与产物

首轮离线输入明确包含以下材料，而不只是一份算法简介：

- 30行完整TRAIN方法/预算表现；
- 24条同graph、同seed的真实运行曲线；
- feature CPU、throughput、原始候选拒绝与执行诊断；
- 严格条件证书、真实结构witness和typed输出合同。

第二轮新增刚完成的144次TRAIN完整调度方法对比、实际controller源码，以及真实成本、曲线、失败与拒绝诊断。LLM据此输出修订配方，并直接选择信用度量、演化间隔、参数扰动、语义结构变异及父子配对竞赛配置。这些输入不包含VAL/TEST优化结果。

非LLM[Grammar银行](../banks/grammar_operators.json)是独立语法初始化对照。调用成本是离线成本，应单独报告；目前不能在缺少实际收费记录时推算美元成本。token和合成时间也不能从在线CPU预算中悄悄删去而对外声称“零成本”。

每条输出配方含结构特征、排序规则、patch政策、评估计划、演化模板、4个系数与解释。结构特征和表达式必须通过严格schema及typed安全解释器。patch最多64节点，超额拒绝，不能静默截短图来改变定义。图权重保持整数微秒，特征的秒语义由显式scale保证；诊断使用精确有理数。

第二轮两份原始响应最初被旧执行器的numeric rule“48节点/depth8”限制排除，原记录保留在[audit_round2.json](../audit_round2.json)。实际输入明确给了结构特征限制，却没有明确排序规则共用该限制；工程上因此在任何第二轮性能计算前将两者分离：结构特征仍最多48节点、depth8；纯数值规则最多256语义节点、depth16、长度2000，仍不允许导入、属性访问或执行任意代码。两次原始模型输出未经修改，由修正后的执行合同重新校验并接受，未重新调用模型或手工修响应。这个变更是共同接口修正，必须随源码版本报告，不能作为LLM收益。

从[两份实际配置](../configs_round2/)实读，Witness与Feedback均选择：

| 第二轮字段 | 真实输出 | 执行含义 |
| --- | --- | --- |
| `credit_metric` | `absolute_signed_gain_per_cpu` | 原始有符号增益ticks/CPU；不除删除权重，负收益保留 |
| `evolve_every` | `32` | 按信用更新计数，不按trial计数 |

| `structural_mode` | `atomic_template` | 实际组合两份LLM完整评分块与相应特征，不只是固定模板切换 |
| `paired_race` | `true` | 父、子方案在相同F/P下比较，双方成本与原始收益都记录 |

## 4. 从离线产物到当前实例内算法

初始化银行给出语义模板；种群不超过4个成员，运行中可更新实际特征、规则、系数及政策。排序惰性读取所需特征，删除节点后缓存更新，图操作只使用声明的残余图语义。`patch_init`保留初始patch，邻域和边操作使用当前active；初始集合统计和当前残余统计不能混用。

完整求解的incumbent、控制器、种群、信用、证据archive、缓存和随机数状态在每次运行时重置。不同TEST配置或来源之间不共享已学运行状态。运行候选可能失败、产生负gain或触发guard拒绝；这些是必须保留并计费的算法轨迹。

LLM不能自行决定非法调度可接受，也不能宣称生成规则具有数学保证。内核承担整数奖励、完整可行性、预算、条件界及完整收益计算。正式结果需要记录结构特征实际被score读取、配方/规则是否改变、是否形成有效替换，以及最终完整收益。只有诊断读取或某个操作被执行，不能证明该特征参与了实际排序，更不能证明它提高质量。

第二轮语义块组合最多3个合法特征；不能形成合法组合时记录unavailable，并明确标记参数/政策回退，不能称为表示修复。初始系数作为语义中心保存，原零系数不通过普通扰动启用。配对竞赛采用相同活动patch和外部承诺，并依据实际可行提案选择赢家；父方案计算也计入总CPU。日志保留子方案原始负增益，即使父方案胜出；接受收益及ranking/exchange分解属于实际赢家，不能按子方案错误归因。

当前表示archive按完整base9加当前全部生成特征建立独立语义空间，不能用base9的循环冒充扩展表示仍有冲突。这项archive校正与numeric规则接口修正属于共同执行器工程变更，不能归为LLM生成策略的贡献。实际结构区分、规则使用与收益仍需分开测量。

43项有意义的工程测试已通过，支持接口、安全语义和实现检查。是否在实际求解中发挥作用必须由完整运行记录回答，不能用测试通过代替算法实验。

## 5. 当前局部证据及不能越过的结论

初始TRAIN P64诊断如下，来源见[结构挑战记录](../analysis/structural_challenge.json)：

| 初始化来源 | 具有区分的配方 | 初始严格规则拟合 |
| --- | --- | --- |
| Witness | 5/6 | 1/6 |
| Feedback | 1/6 | 0/6 |
| Grammar | 1/6 | 0/6 |

分母是各组6条配方，诊断范围是该TRAIN P64挑战。它不是全部训练实例、全部严格关系的通过率，更不是完整调度质量。Witness较多表达式能区分该见证，是局部信息诊断；规则拟合仍弱，正说明“可区分”到“正确评分”之间存在缺口。

正式解释必须沿以下链条分别给证据：表示消除冲突 → 结构特征被实际排序读取 → 候选产生/接受有收益的替换 → 完整调度质量改善。任何一环为零、负差或成本过高都如实报告。若完整质量改善来自共同经典搜索组件，而非生成特征或见证机制，必须相应限制贡献归因。

## 6. 既有正式工作与原创性边界

[FunSearch，Nature625（2024）](https://www.nature.com/articles/s41586-023-06924-6)已经将LLM程序生成与系统性评价相结合。[EoH，ICML2024](https://proceedings.mlr.press/v235/liu24bs.html)已经结合LLM与演化计算来发展启发式的文字描述和可执行代码。因此，LLM生成规则、用进化搜索改进程序、生成自然语言解释，都不能单独作为本工作的原创结论。

最新的[LACE，Nature Machine Intelligence（2026-10-01）](https://www.nature.com/articles/s42256-026-01307-8)在官方摘要中明确使用输入/输出schema、工具库、启发式portfolio以及预算内的互补演化。这与本轮扩展LLM输出和成本组合存在明显重合。仅改变输出内容数量、增加多个候选或称为ensemble，并不能构成充分的新颖性。这里的比较依据官方摘要；在未完成全文逐项对照前，也不能反向断言LACE完全没有相似的证据机制。

本工作应检验的区别是：**通过可验证的决策矛盾定位表示不足，利用结构见证定向生成区分特征，并在当前实例内检验和演化对应搜索配方**。条件证书、表示冲突与特征代价的联系是候选贡献位置；它是否区别于已有方法、是否减少无效规则修补、是否转化为完整收益，都需要完整实验及进一步文献比较，当前不能写成已经成立的原创性和优势。

## 7. 完整比较计划与报告要求

开发比较为16个TRAIN图、9方法、seed2、10 CPU秒，共144次。正式比较为32个TEST图、9方法、seed2、10/30 CPU秒，共576次。9方法及银行、可用配置、源码和图hash均按[PROTOCOL](../PROTOCOL.md)注册。开发检查不能根据TEST表现改设计。

正式方法包括LLM Witness、LLM Feedback、同动态内核Grammar、固定Witness、受限base9 Witness、Degree、原生CHILS两种population以及CP-SAT。CHILS参考[SEA2025正式论文](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.SEA.2025.22)，CP-SAT参考[CP2023正式论文](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.CP.2023.3)；本报告未引用arXiv。

## 8. 应放入discussion的局限

数据由定制STK场景构建，包含EOP预测值；只有完整可见窗口和时长目标，没有队列、存储、电量或任务截止期。当前只研究有效地面资源轴：此前卫星150→600秒对可行集无独立作用，不能用它宣称多轴适应。新版尚未完成公开算法benchmark验证。

特定TRAIN见证中的严格表示矛盾不保证每个实例都频繁出现；消除矛盾也不保证产生收益。结构特征和当前证据可能降低throughput，动态控制可能不如经典组件。冷启动静态配置比较无法回答warm复用或求解中途变化的效果。这些都需要如实解释，不以“LLM热点”或“模块有信息”替代性能证据，也不作最优性或论文录用保证。
